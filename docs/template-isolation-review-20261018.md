# 模板检测隔离修复与审查（2026-10-18）

> 0.9.9 发布归档（2026-10-20）：本文保留此阶段实现和当时检查数量，不作为当前发布状态或完整硬件验收的声明。当前操作以[用户指南](user-guide.md)、[实现说明](development-0.9.9.md)和[发布检查](release-checks-0.9.9.md)为准。

## 问题与修改

旧流程虽然关闭了临时配置中的 MTP 和视觉开关，但仍复制完整运行配置。资源记录失效后，显式思考开关可能保留、验证标志却已清除，导致通用参数校验报“思考开关必须通过当前模板及 Responses 路径验证后才能设置”。未启用功能残留的路径、参数及旧默认值也可能干扰模板检查。

新增 `TemplateValidationProfile.Create`，从空白配置构建文本模板渲染检测所用的临时配置。仅复制主模型身份与来源、GPU/设备/专家放置、Flash Attention、KV 缓存类型、已知加载参数及待检模板路径。上下文沿用检测专用的 4096、并行 1；思考、MTP、视觉、n-gram、运行扩展、自定参数和旧默认值均不带入。生成和添加模板共用该入口。

## 审查结论

- 正常启动的通用验证器未改动；失效的思考验证仍会拦截正常启动。
- 原生渲染客户端、消息顺序和工具标记检查未改动，渲染通过不代表思考、视觉或 MTP 已验证。
- 临时配置仅交给临时 Router preset 生成器，原始配置仍用于模板签名和登记，不回写用户参数 JSON 或启动预选。
- 有效模板记录继续查重；运行库更新导致记录失效后可重新检测。新生成模板使用独立文件名，既有模板内容不变，其他能力登记不被更新。
- 模型及模板路径保护、主文件存在性、模板目录约束、运行状态拦截、检查期间来源变化检查、临时文件清理沿用原逻辑。
- 诊断仍走已有 `template_generate` / `template_add` 操作及准备渲染、登记、成功或失败阶段；没有新建日志机制。

未发现本次修复引入的严重问题。模板本身错误、主模型加载失败、资源占用等真实检测失败仍会如实报错。

# 0.9.8 资源管理实现审查 — 2026-10-16

> 0.9.8 发布归档（2026-10-18）：本文保留本阶段源码与当时检查结果；其中测试数量、待验证/未发布状态及阶段性界面规则不代表最终发布状态。当前操作与最终范围见[用户指南](user-guide.md)和[发布检查](release-checks-0.9.8.md)。

本次对照已确认方案进行了源码自审、自动化回归及隔离 WPF 检查。审查范围为资源管理入口、重复操作、资源登记移除、配置引用、参数下拉刷新和新启动校验；不将其描述为独立第三方审计。

## 实现与边界

- 新窗口固定绑定打开时选择的主模型；多次添加后即使主界面列表重新载入，也不会失去目标模型。四个原有资源操作改为显式传入该模型。
- 查重使用规范化路径和有效的既有证明；记录仍绑定具体主模型。视觉匹配原有模板依据，兼容模板复用当前生成结果，不修改现有配置的选择或预选。
- 移除按资源种类及路径清理所有对应证明，保持其他资源和其他模型文件原样；实体模板、外挂文件始终保留。检查所有配置而不只检查预选，无法检查时拒绝移除。默认模板标记随登记清除。
- 资源文件缺失只使证明失效，JSON 的路径和开关保留。启动入口读取最新 JSON 并校验，不回退到旧 BAT、Catalog 或 Router preset。关闭的功能保留现有启动规则。
- 服务及检测限制在界面和移除提交前再次检查。参数页及资源窗口采用模态操作；外部程序仍能编辑文件，启动时保留既有检查作为最终防线，未宣称能锁住资源管理器。
- 内置 MTP、模板、视觉按内置能力展示，没有实体文件移除操作。没有新增内置 MTP 验证步骤；现有检测算法及验证范围均保持不变。

## 审查中修正的问题

1. 模板检测取消后，旧缓存可能仍有效。新增“本次渲染检查完成”结果标记，取消不登记。
2. 规范化路径查重与原先精确字符串匹配不一致。资源匹配、模板启动检查、参数菜单选择统一使用路径身份比较。
3. 唯一外挂仍被 JSON 引用时缺少解除选择入口。无内置替代项时提供“未选择”，只清除来源路径；开关由用户自行关闭，保存后可以移除登记。
4. 成功提示曾声称开关保持关闭，实际新流程不改写已有 JSON。改为明确提示“已登记、已有配置未改变”。
5. 限制长操作结果的页面高度，避免多个配置引用提示挤出列表；完整结果仍通过提示框及悬停提供。状态文字使用正常字重。
6. 规范化路径相同但大小写不同，直接复制旧指纹会使后续校验误判。新增两个测试确认原实现失败后，修正证明映射：仅在原记录仍有效、文件身份及上下文一致时，为当前路径写法映射指纹，并复查原证明。原记录、JSON 和功能开关不被改写，原生验证方式不变。

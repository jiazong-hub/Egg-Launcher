# 运行参数设置全面审查：思考验证关联修复（2026-10-07）

> 本文是 2026-10-07 的历史审查快照。其中思考关闭禁用档位及原区域排序已由后续修改替代；当前机制见[思考模块与确认操作审查](thinking-independent-review-20261008.md)。其余原审查证据按当时版本保留。


## 本次范围

仅修改思考验证指纹关联、有效旧指纹迁移、原因诊断和显示偏好的保存/启动检查。版本仍为 0.9.7，Profile schema 保持 13；新指纹规则为 5，兼容准确匹配的 v4 结果。未修改模板生成、原生能力检测、推理、SSE 显示处理、界面布局、运行中编辑限制或配置事务结构。本审查完成时尚未发布 GitHub Release；后续正式发布流程见 release-checks-0.9.7.md。

## 实现及审查修正

- 思考指纹排除 25 个明确的资源/性能参数键：fit、fit-target、fit-ctx、threads、threads-batch、load-mode、lazy-mode、n-cpu-ffn、split-mode、tensor-split、main-gpu、numa、override-tensor、kv-offload、no-kv-offload、repack、no-repack、op-offload、no-op-offload、no-host、ctx-checkpoints、swa-checkpoints、keep、cpu-moe、n-cpu-moe。增删或改值不影响该验证，参数仍正常生成。RoPE、YaRN、SWA、思考覆盖和未知参数仍参与检查。
- 模型、模板/Jinja、Runtime/DLL、配套 CLI 的检查保留。没有按时间失效机制。
- 旧验证只在原 v4 指纹仍精确匹配时迁移，新旧算法不以忽略错误或读取失败作为有效依据。编辑器在改参数或恢复默认前迁移原 Profile；自动适配也在应用建议前迁移。保持验证时间和能力结果。取消编辑不落盘。
- 每个依据保存组件摘要，用于说明具体变化，不保存提示词，也不用于猜测能力。旧失效记录没有可对比的组件信息时明确说明无法细分变化项，不虚构原因。文件读取失败单独提示。
- 显示开关偏好保留，只有原生思考可用且有效开启时才构成实际启用需求。与显式思考开关、档位调节的严格检查区分；真实失效会清理能力并同步禁用实际显示。所有相关保存、启动及代理启动检查使用同一条件。
- 新诊断字段是可选 Profile 元数据，不加入模型参数默认快照，所以迁移不会误使现有上下文滚动能力缓存失效。

## 运行参数全面审查

逐项检查基础参数、思考设置、视觉、MTP、高级参数、沙箱、模型信息，以及保存、恢复默认、保存为默认、取消和当前/非当前模型同步入口。

- 基础参数：Context/安全余量/工具上限、SSE 步进、Batch/Micro Batch、设备及缓存参数的原有校验保留。真正运行中模型仍禁止编辑，不放宽权限。
- 思考设置：原能力与用户偏好隔离，默认档位与实际传递共用既有选择逻辑；反转不改变档位值。关闭/不可用/检测中联动保持。
- 高级参数：相关参数仍失效，无关资源参数解除关联；未知参数不放行。非法线程值及受管理参数覆盖检查保留。
- 视觉、MTP：源文件、验证、原生 Runtime 能力门、参数范围、上下文移位互斥及已有校验不变。未把思考排除规则推广到其他能力。
- 沙箱：保持独立设置、路径验证、未编辑原值保留及现有配置事务，不将其加入思考指纹。
- 默认恢复：参数快照与能力证据分离；已验证原结果先迁移，恢复无关资源值不清档位。模板相关默认变化仍重新检查。
- 配置同步：当前 Local 模型走原事务，其他模型不覆盖当前配置；失败回滚和在线恢复由现有测试验证。显示偏好不再单独阻止已清理能力后的同步。

## 验证结果

- 439/439 自动测试通过（0 跳过）。包含全部既有配置事务/回滚、模型、MTP、视觉、沙箱、滚动能力及传输测试；新增 46 项参数关联、旧结果迁移、无时间失效、读取失败、具体原因、实际启用条件和保存同步验证。
- Release 构建零警告、零错误。格式及 diff 空白检查通过后打包。
- WPF 实际控件捕获验证 23 项修改，检查 fit/线程/设备/分割/加载/计算优化/KV 类型/Flash Attention。保持全部思考偏好及验证时间；恢复默认、取消隔离、非法线程、真实模板变化通过。
- 既有 WPF 三区域布局、默认强度、反转和显示联动、检测中置灰、未确认状态、缺失模板和取消提示检查通过。
- 当前 Local 模型的真实文件事务与模拟 Codex 配置：修改 fit/线程保存成功，配置默认 medium、显示开启；模板真实变化后保存仍成功，显示偏好保留但配置实际显示关闭，在线模式原字段恢复。
- 后台启动：实际依据变化时，客户端关闭可同步清理；客户端运行时仍阻止沿用原结果。清理后显示偏好保留，不阻止同步。

没有发现阻碍测试包交付的问题。未启动用户模型或操作正在运行的 Codex；真实 GPU 和 GGUF 推理仍由用户实机验收。此前已丢失或真正失效的验证不能凭偏好自动恢复。

# 0.9.8 视觉资源选择与开关修复审查

> 0.9.8 发布归档（2026-10-18）：本文保留本阶段源码与当时检查结果；其中测试数量、待验证/未发布状态及阶段性界面规则不代表最终发布状态。当前操作与最终范围见[用户指南](user-guide.md)和[发布检查](release-checks-0.9.8.md)。

日期：2026-10-18。状态：修改完成，未正式发布。

## 原因与处理

模型管理成功添加视觉模块后，参数页仍按当前 JSON 的聊天模板过滤资源；解析资源能力时也要求识别记录与 JSON 使用相同模板。使用不同模板的 JSON 因此看不到已登记模块，或无法取得可启用的视觉状态。

视觉现有检查是 GGUF 元数据识别与 Runtime 选项检查，没有进行模板渲染或图像推理验证。本次去掉参数页和能力解析中的“模板必须相同”条件：先确认原资源记录仍有效，再将视觉识别状态与签名绑定到当前 JSON 的选择。保留原有指纹算法、原记录有效性检查和资源登记规则，不将元数据识别宣称为模板兼容或图片推理已经验证通过。

参数页同时修正：

- 列出模型管理中所有仍有效的视觉记录，用户选择后可开启视觉。
- 已登记资源但尚未选择时，提示从下拉菜单选择，不再误报为没有视觉验证记录。
- “内置视觉”和“未选择”均使用空外挂路径，但按来源区分，避免选择状态混淆及点击内置项不触发更新。
- 未配置内置来源且没有对应资源时显示“未选择”，保留具体失效路径的不可用提示。
- 来源改变时同步外置视觉详情区域。
- 视觉页移除下拉框下方重复的“视觉投影文件（mmproj）”标题；保留原有下拉框底部间距，后续参数自然上移，内部路径控件及选择、保存逻辑不变。

没有自动选择外挂、开启视觉或写入现有 JSON。保存／应用仍遵守原有语义，MTP 流程不变。不增加视觉联合加载、测试图片、推理调用或任何新的验证入口。

## 边界审查

- 原识别记录失效、主模型／外挂／Runtime／视觉库变化时，不能据此重新授予视觉状态。
- 当前 Runtime 明确不支持 `--mmproj` 时仍禁止启用。
- 模板路径限制及模板自身的检查保持不变；思考验证也继续沿用其模板依赖。
- 当前 JSON 已请求开启但证据失效时不静默关闭配置；原有保存与启动校验继续拦截无效请求。
- 读取、选择和能力复用不改资源登记或模板文件，用户保存后才写入参数 JSON。

# 0.9.9 实现说明

发布日期：2026-10-20。本轮从批处理参数 `-b` / `-ub` 的扩展开始，包括 n-gram、自定参数、资源重新检测、验证边界调整、整数 K 输入和接受率展示。本文按 0.9.9 源码记录实现；发布范围见[发布说明](release-notes-0.9.9.md)，验证和用户反馈见[发布检查](release-checks-0.9.9.md)。此前阶段测试数量保留为历史，不扩大为完整硬件矩阵验收。

## 已实现范围

- 批处理与物理批处理下拉菜单增加选项，支持自行输入正整数；保留默认与显式数值的区别，显式物理批量不能大于显式逻辑批量。
- 推测解码支持五种 n-gram 策略及其参数，可独立使用或与 MTP 组合，默认关闭。具体行为与验证边界见 [n-gram 实施说明](ngram-implementation-review-20261018.md)。
- MTP 增加 `--spec-draft-n-ubatch`、`--spec-draft-sampling`，外置 MTP GPU 层数支持非负整数、`auto`、`all`。
- 基础参数的 MoE 区增加 `--moe-cache-mib`。
- 高级参数增加 `--cache-ram`、`--cache-prompt` / `--no-cache-prompt`、`--cache-idle-slots` / `--no-cache-idle-slots`、`--checkpoint-min-step`、`--kv-unified` / `--no-kv-unified` 和实验性 `--backend-sampling`。后者只有默认与开启，不生成不存在的反向命令。
- 增加实验性“自定参数”选项卡，分为 llama.cpp 与 Codex 两组，按行保存名称、值和 llama.cpp 无值开关状态。

## JSON 与参数传递

扩展固定参数保存在 `RuntimeParameters`；自定参数保存在 `CustomParameters.Llama` 与 `CustomParameters.Codex`。所有选择及未启用时保留的数值均写入 JSON。启动生成时，仅输出当前启用功能所需的参数；未设置项目继续沿用接收程序的默认行为。

这些新设置或 n-gram 存在用户意图时，配置文档使用格式版本 2，让旧版本启动器拒绝不支持的文件，避免静默丢弃字段。旧配置继续可以载入；不允许被静默修正或删除的冲突行会显示在页面内供修正。历史手写、没有固定界面的 `ExtraArguments` 项在编辑页显示为自定参数，只有用户保存后才写入新的存储位置。

llama.cpp 行进入模型的 Router preset 和 BAT，保留长短命令的实际拼写。每行值代表一个参数，第一版不支持多值命令。为避免两种生成文件含义不同，值不接受双引号、`#`、`;`、控制字符及首尾空白；需要无值命令时明确选择无值开关。

Codex 行左侧为不带 `--` 的键名，支持普通点分路径；右侧是一个完整 TOML 值，类型由用户填写，启动器不猜测或转换。数组和内联表是单个 TOML 值，不等于 llama.cpp 的多值命令。保存只修改 JSON；真正启动本地模式时，才经既有配置事务写入 Codex。该功能不会传递额外的 Codex CLI 启动命令。

## 保存检查

保存、应用、另存共用检查：

- 固定参数、默认参数和启动器自动管理字段均保留，不能通过自定参数覆盖。
- 同一接收者内，命令相同、已知别名重复、相反开关重复均拒绝，数值相同也不例外。
- Codex 父子键路径冲突同样拒绝；不同接收者分别检查。
- 不正确的命令格式、无法完整表达的值、TOML 语法错误及额外赋值注入均拒绝。
- 冲突行保留供用户删除，不自动合并、改写或丢弃。
- 不要求未知实验参数出现在当前运行库帮助里才能保存；其实际支持与效果由接收程序决定。

已知别名依据 llama.cpp 官方 `common/arg.cpp` 登记为静态数据，保留大小写区别，例如 `-c` 与 `-C`。未知的未来别名无法预先保证识别。

不增加启动时重复执行的完整编辑检查。原有配置解析、文件生成和事务写入保护仍执行，防止手工修改 JSON 绕过页面后覆盖自动管理字段或注入生成文件。手改 JSON 不能视为已通过页面检查。

只拒绝明确直接矛盾的组合，例如显式缓存容量为 0 却开启空闲槽缓存；不联动修改无关参数。

新增固定参数的界面采用支持、明确不支持、未知三种状态。未知时允许编辑和保存，适用于其他本地模型正在运行而不能执行检测的情况；明确不支持且没有保存值时置灰，已有值保留供清理。恢复为支持状态时恢复原功能说明。该判断不修改 Dense/MoE 的显示范围，也不绕过启动前的运行库支持检查。

## Codex 原生配置恢复

自定字段纳入现有事务的原值、已应用值、上次已应用值与恢复记录，不建立另一套配置写入路径。

- 在线→A→B 时保留进入本地前的基准，B 不使用的 A 字段恢复原值；原来不存在则移除。
- B 新增的字段从进入本地前的备份捕获基准；若该字段已被外部修改，则停止覆盖。
- 更新回滚、未完成事务恢复、端点迁移、切回在线和既有卸载恢复调用使用同一套字段记录。
- 编辑单个表字段时保留兄弟字段与注释。已拥有的自定字段被外部修改时停止自动覆盖；无关字段修改得以保留。
- 数组表路径、向已封闭的内联表新增字段等无法安全合并的结构，在写入前停止。已有内联表叶字段可修改并恢复。
- 同一次本地事务中，自定键由父键改为子键或反向改变结构时，先切回在线再使用该配置。

恢复原生字段不等于整个配置文件逐字节相同；继续保留 0.9.8 已有的未激活本地历史 Provider 兼容行为。认证开关及在线模式规则没有改变。

## 日志与验证

复用现有简易/详细模式。简易日志记录自定参数接收者、名称、保存拦截与模式切换结果；详细日志增加批处理数值、扩展固定参数、生成与配置事务阶段。任意自定值可能包含密钥或私人路径，因此新增结构化事件不转储自定值；不得用“进程已启动”声称实验参数已生效。llama.cpp 原生输出继续沿用现有记录与脱敏规则，不能据此保证引擎自行输出的任意文本都已脱敏。

能力检测不运行用户自定参数；思考、模板和外挂检测方式保持原有流程。上下文滚动验证的指纹不受 Codex 自定设置影响。

模板生成与添加共用独立的文本渲染临时配置，仅保留主模型身份、加载设置和待检模板，不继承思考、MTP、视觉、n-gram、自定参数及旧默认参数的状态或路径。旧思考记录失效、外挂缺失不能阻止模板渲染检查；仍沿用原生 `/apply-template` 检查，不据此认证其他能力。保留运行中禁止检测、模板目录限制、有效记录查重、来源变更复查和文件保护；失效记录可重新检测。此临时配置只写入临时 Router preset，不保存到用户 JSON，也不改变启动预选。修复审查记录见 [模板检测隔离审查](template-isolation-review-20261018.md)。

本轮审查与测试结果见 [参数扩展审查记录](parameters-0.9.9-review-20261018.md)。真实模型兼容性、显存占用和性能需测试机实测，未据此宣称 n-gram 或新参数一定提高速度。

## 资源重新检测（2026-10-19）

模板、外置 MTP、视觉列表增加行内重新检测，有效/失效记录及旧配置中尚未登记的引用均可原路径复查，无需解除配置引用。成功更新原登记；明确拒绝清除对应证明并标记失败，取消、超时或服务不可用保留原记录，是否仍有效继续由原指纹判定。检测前后核对主模型、资源和运行库，依据变化时不登记结果。内置模板明确失败后禁止继续按内置模板启动，成功复查后解除；未检测过的内置模板保留原启动规则。内置 MTP 不新增独立验证。

MTP 探测使用独立临时配置和原有联合加载、极短 `/completion`，不继承失效思考、视觉或聊天模板状态；保留主模型及外置 MTP 的必要加载设置。视觉添加和复查仍仅为元数据识别及运行库选项检查，记录不再依赖所选聊天模板。运行中禁止检测、目录约束、移除引用保护、JSON 和预选保存规则均沿用。详情见 [重新检测审查](resource-recheck-review-20261019.md)。

## 检查边界与验证记录复用（2026-10-19）

- 保存、应用、另存检查格式、范围、明显依赖冲突、模型绑定、路径和自定命令重复；不要求当前取得运行库支持信息或所有能力证明仍有效。已填写的合法资源路径暂时缺失时可以保存，用户请求的开关和路径不会因此被静默清空。应用仍只增加启动配置预选。
- 新启动继续重新读取 JSON，检查实际启用功能的资源、证明与运行库支持。Jinja 关闭时不读取未使用的模板；启用时保留原有模板检查。
- 思考检测独立收集必要加载设置和当前模板，不再调用全页保存检查，也不继承 MTP、视觉、n-gram、自定参数、旧默认值和 `keep`。原生渲染及 Responses 检测方法不变；没有取得新的完整证据时不覆盖仍有效的原证明。
- 上下文滚动使用独立的原生 completion 检测配置，保留当前上下文、内存、加载和实际启用的 MTP 依赖。显示顺序、休眠时间、模板、已关闭能力的参数和文件不再使它失效。检测配置与指纹采用同一份依赖投影。
- 视觉证明升级为主模型、视觉文件及来源的元数据依据；更改模板、运行库或 mtmd 文件不再撤销已完成的元数据识别。当前运行库是否能运行视觉功能仍单独处理，不以识别记录代替图片推理验证。
- 登记不按时间或启动器版本删除。旧视觉、思考和滚动证明仅在旧依据精确匹配时迁移；无法确认的旧证明保留登记供单项重新检测，不批量授权。不会自动恢复被移除的资源登记。
- A 运行时，未运行 B 的名称、类型和配置仍可编辑；检测保持全局禁止。模式卡片主体淡化不再连带淡化可用的三个入口，正在运行模型的三个入口仍不可用。
- 复用原日志模式：简易模式保留操作、拦截和结果；详细模式补充本次保存/能力检测的验证范围与阶段，不增加配置正文或自定值转储。

审查记录见 [检查边界审查](validation-boundaries-review-20261019.md)。

## 输入、提示与界面（2026-10-20 定稿）

`ProfileEditorWindow` 的 Context、压缩安全余量、工具结果历史上限统一使用整数 K 输入。`FormatKInput` 负责载入显示，`TryParseContextSize` 将新整数输入乘 1024；JSON、生成器和 Codex 仍使用 tokens。旧配置非整 K 值仅在显示与原值完全一致时保持原数值，不静默舍入或迁移。现有 `LongConversationLimits` 不变，整数 K 候选范围由真实 token 边界向内换算。

中英文参数提示补齐接收者、命令/配置键及用途，保留路径、动态范围和运行库支持提示。沙箱位于自定参数之前，自定参数为最右页；Dense/MoE 只显示适用项。模型列表入口顺序为模型管理、编辑运行参数、显示/隐藏、从列表移除。资源行的重新检测保留文字按钮，移除位于最右侧，使用圆圈叉号和悬浮说明。

## 最近一次草稿接受率

`DraftAcceptanceParser` 只读取 llama 的单请求 Slot timing summary，排除全局累计统计、过程接受记录及无效计数。保留原生比率和 accepted/generated，不估算或合并请求。进程输出读取发生在诊断日志过滤之前，写日志失败后的排空流程也继续提取。

`LlamaRouterProcessManager` 用内存保存最后有效统计，启动/停止清空；`LocalRouterSupervisor` 仅对实际运行且启用 MTP 的模型，通过现有 RuntimeState 发布。没有变化时维持原心跳，有新结果在下一次现有协调周期发布，不增设高频轮询。MTP+n-gram 标明整体草稿统计。

界面按可信 Router 身份、进程启动时间、模型、阶段和状态新鲜度接收。同一次运行无新统计则保留，真实零值显示 0.0%；无结果、未启用 MTP、换模型、重启/停止服务或在线模式显示短横线 `–`。速度、接受率、上下文同排，速度缩写为等价的 t/s，字号沿用侧栏自适应。完整依据见[接受率与界面审查](draft-acceptance-review-20261020.md)。

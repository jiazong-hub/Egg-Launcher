# 思考档位显示顺序开关：修改与小规模审查

## 行为

在思考设置的“允许在 Codex 中调节思考强度”下方增加“反转档位显示顺序”，默认关闭。说明为：如果 Codex 中的思考档位顺序与预期相反，可开启此项。保存后生效；仅反转排列，不改变档位值。

这是每个模型独立的偏好，支持保存为模型默认和恢复默认。关闭时沿用检测结果中的列表顺序；开启时仅在生成 Codex Catalog 时反转。自定义档位同样只改变位置，不改名，不猜测强弱。不修改模型原始档位列表、默认档位、模板或检测指纹规则，因此仍有效的既有检测结果不需要重做。

保存沿用原有配置事务。当前本地模型的目录立即同步；其他模型保存其偏好，在切换到该模型时生成相应目录。不会覆盖正在使用的其他模型配置。

## 审查

本次变更范围内未发现需继续修正的逻辑问题。

- Catalog 生成时按反转后的原始值生成完整对象；effort 和 description 始终对应，不存在分别反转两份数组的过程。
- 默认档位继续按字符串保存，与位置无关；没有新增位置编号到档位名称的映射。
- 反转操作不修改原始列表，重复保存不会再次翻转检测结果。
- 切换思考状态、UI 刷新及检测过程保留显示偏好；检测期间禁用此开关。
- 参数保存、保存为模型默认和恢复默认均包含此偏好；取消编辑不会修改原模型对象。
- 原生运行 preset、请求中的 effort 处理、模板验证和指纹规则未改动。

## 开关联动的小规模复审

在追加“仅上方档位开关可用且开启时允许编辑反转开关”的修改后，复审状态刷新、Checked/Unchecked 事件、保存候选和配置生成链路，未发现需要修复的问题。

- 刷新时的 `_populatingReasoning` 防止程序赋值触发事件递归或覆盖用户偏好。
- 关闭上方开关立即禁用下方开关，但不清除反转偏好；保存候选也保留该偏好，重新开启后恢复。
- 上方档位未确认、Responses 未确认、客户端兼容性未确认、思考关闭或检测进行中时，下方均不可操作，即使已有偏好为开启。
- 上方关闭时 Catalog 不输出思考档位，保存的反转偏好没有实际输出效果。
- 此次只调整界面启用条件和状态刷新，不改动原始档位值、描述、默认档位、检测指纹或第一项文字样式。
- 扩展的真实 WPF 编辑器检查全部通过，覆盖上述状态及保存候选、取消隔离；相关自动测试 28/28 通过。

## 问题与修改

测试机 Router 启动成功，但 `router_started.runtimeVersion` 为 `unknown`。原实现只读取 Windows 文件资源中的 `ProductVersion`，没有从 `llama-server --version` 获取版本；文件未提供该属性时不能识别实际构建。

新增 `LlamaRuntimeVersionReader`，复用已有 `IProcessRunner` / `ProcessRunner` 调用方式，只执行 `--version`，不执行 `--help`、设备枚举或模型验证，也不传入模型路径。解析标准输出和错误输出中明确以 version/build 开头的版本行；跳过 CUDA 初始化等提示，保留构建号和可识别的提交标识，日志不保存整段命令输出。

取值顺序为命令版本、Windows 产品版本、Windows 文件版本，均不可用时保留 `unknown`。查询使用 3 秒超时；超时、非零退出、无法解析、进程异常均回退到文件版本，失败不作为 Router 启动的准入条件。调用方主动取消仍保留原取消行为，清理查询进程。

Agent 内保存当前程序路径、文件长度和修改时间对应的内存结果。程序未变化时，端口重试、健康轮询和异常重启均复用结果；路径或文件信息变化后重新查询。不增加缓存文件、设置项、依赖或后台计时器，不修改模型参数 JSON、认证传递、能力检测或 llama.cpp 运行参数。

`router_started` 在原记录中补齐：

- `runtimeVersion`：版本或构建标识。
- `runtimeVersionSource`：`version_command`、`product_version`、`file_version` 或 `unavailable`。
- `runtimeVersionQueryResult`：详细模式记录 `success`、`timed_out`、`nonzero_exit`、`unrecognized_output`、`query_failed` 或 `executable_unavailable`；简易模式不填查询过程分类。

## 审查与验证

- Release 解决方案构建通过，0 警告、0 错误；格式检查及 diff 空白检查通过。
- **646 项自动化测试通过**，其中新增 23 项版本相关检查。覆盖前置初始化提示、双输出流、构建与提交标识、未知格式、超时及非零退出的误导输出、文件版本回退、程序变化、文件缺失、主动取消，以及前后台共用 Supervisor 的端口重试、轮询和恢复路径。
- **8 项隔离真实进程检查通过**。使用测试专用 apphost，实际执行标准输出提示与错误输出版本，验证 3 秒超时后子进程退出、回退到产品版本，以及主动取消时不遗留子进程。测试进程的超时路径样本约 3.03 秒，不代表所有磁盘和杀毒环境的时间上限。
- 审查中补齐纯字母十六进制提交标识的解析，避免将有效提交误判为未知。
- Supervisor 单元测试统一注入版本查询测试桩，避免将占位用的伪 `.exe` 当作真实程序执行；实际进程行为另由上述隔离检查覆盖。

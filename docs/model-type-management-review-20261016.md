## 范围和结论

本次完成模型类型入口迁移、登记单独更新，以及类型不匹配配置的拒绝载入和新启动保护。经过源码自审、自动化测试和隔离 WPF 检查，本次范围内未发现剩余阻塞问题。这是本次实现自审，不是独立第三方审计。

## 已确认的数据规则

1. 类型页显示自动识别、当前类型及来源。选择不会立即保存，不覆盖自动识别结果；保存只修改登记中的两个类型字段。
2. 所有用户 JSON 文件保持原字节、路径和文件名。类型保存不调用旧的重建配置流程，不修改资源证明、启动预选或运行生成物。
3. 主模型身份和类型检查分开；另一模型的配置始终拒绝，当前模型的另一类型配置同样拒绝。失败保留原编辑状态，没有载入时只提供内存默认草稿。
4. 预选路径保留，类型不匹配显示不可用；改回原类型后恢复适用。用户主动保存或另存参数继续遵循原有保存规则。
5. 正常新启动和后台 Agent 新启动共用 ModelStartupConfiguration；类型校验发生在运行文件生成之前。现有会话的运行快照逻辑保持不变。
6. 修改 GGUF 标签分类不会改写权重或指定新的实际架构；自动识别和原生验证方法没有改变。

## 审查中处理的边界

- **旧登记字段阻止反向切换**：旧 MoE 专用参数仍可保留在登记中，但登记结构检查不拿它们当当前运行参数；用户 JSON 和启动参数仍执行原有校验。
- **其他类型配置的资源引用**：引用检查不使用普通参数载入接口，避免因类型不一致漏查或阻塞所有清理；只返回文件引用信息，不能绕过运行载入限制。
- **过期编辑窗口**：保存及载入前检查最新登记类型，外部类型变化会要求重新打开，不能把旧窗口类型写回登记。
- **自动参数适配入口**：增加计算前和写回前的当前预选类型检查，移除参数保存入口更新登记类型的能力，防止间接覆盖旧类型 JSON。
- **外部并发编辑**：类型更新保留未知登记字段，提交前检查原内容摘要及服务状态；发生变化时拒绝覆盖。被删除或损坏的配置不会因类型修改被重建或修复。
- **无法识别的旧配置**：未指定类型的 JSON 也不会被自动修改；用户先指定模型类型，再主动保存新的适用配置。未知模型在参数页仍要求先进入类型页指定 Dense / MoE。

# 0.9.9 检查边界与验证记录复用审查（2026-10-19）

> 0.9.9 发布归档（2026-10-20）：本文保留此阶段实现和当时检查数量，不作为当前发布状态或完整硬件验收的声明。当前操作以[用户指南](user-guide.md)、[实现说明](development-0.9.9.md)和[发布检查](release-checks-0.9.9.md)为准。

本轮修正已复现的过度拦截和证明失效范围，不改变模型验证方法、llama 调用协议、模型选择规则或在线配置恢复事务。源码、依赖门禁和 WPF 夹具验证通过后方制作测试包；真实模型及安装验收仍待测试机执行。

## 修改与边界

| 操作 | 保留的检查 | 不再作为前置条件 |
| --- | --- | --- |
| 保存、应用、另存 | 结构、范围、明显依赖关系、路径与模型绑定、自定命令冲突、目标模型未运行 | 当前运行库信息可得、能力证明有效、保留路径对应文件当前存在 |
| 思考检测 | 主模型、当前模板/Jinja、必要加载控制、原生渲染与 Responses | MTP、视觉、n-gram、自定参数、旧默认值、全页编辑有效 |
| 滚动检测 | 主模型/运行库、上下文与加载内存参数、实际启用的 MTP、原生 completion | 模板/思考显示、休眠、关闭的能力、实验参数 |
| 实际启动 | 重新读取 JSON、所启用资源和有效证明、运行库支持、原有生成/事务保护 | 关闭功能保留的文件是否存在 |

模板的后置 ModeSwitch 文件检查增加 Jinja 条件；外部模板目录限制始终保留。视觉查重、资源解析和证明不再依赖模板。视觉元数据证明独立于运行库文件，运行时兼容仍由原检查与正式加载确认。

保存及登记迁移不再静默清除思考/MTP/视觉请求；修改模板导致思考证明失效时保留用户请求并在启动时要求有效证明。没有完整新证据的思考复查不会覆盖原有效证明。模板/MTP/视觉的明确拒绝、取消、超时及服务忙继续采用之前的更新规则。

滚动检测配置和新版指纹共用 `ContextShiftProbeProfile`。只保留实际使用的加载/内存设置，关闭的附件不进入文件戳。滚动 v1、思考 v4/v5 和视觉旧证明只在精确依据可确认时升级，不改变原验证时间；无法确认的登记仍在，需针对该项重检。检测期间依据改变不会将旧检测结果写为新依据的证明。

名称/类型保存与原生检测分别使用现有目标模型编辑及全局检测规则。卡片只有主体随模式锁定淡化；三个按钮继续使用原有目标模型是否可编辑的判断，点击仍不选择模式卡片。

# 0.9.1 公测版安全与稳定性复核

复核日期：2026-09-21

## 源码与发布门禁

- 程序集、文件、产品信息、标题栏、关于页和内置法律文档统一为 0.9.1。
- Release 全解决方案构建为零警告、零错误；`dotnet format --verify-no-changes` 通过。
- 249/249 自动化测试通过，0 失败、0 跳过。
- 发布后 `Launcher.Agent --self-test`、自包含运行时许可收集、包内哈希生成、ZIP 解压及逐文件比对均由发布脚本强制执行。
- 源码仓库忽略 `.tools`、`artifacts`、`bin/obj`、日志、压缩包和私钥材料；发布包记录源码树 SHA-256。

## 配置、账户与并发安全

- 不读取或复制 `auth.json` 内容，不整目录覆盖 `.codex`；只管理已声明的 Provider 和模型字段。
- 原官方配置继续使用 DPAPI CurrentUser 加密恢复点、两阶段恢复记录、模式/配置跨进程锁和提交前文件哈希检查。
- 设置保存采用串行合并，避免主题、语言、开机启动、模型选择等异步保存互相覆盖。
- 托盘显示、隐藏、退出和窗口关闭由统一生命周期门控制，避免退出过程中重新显示窗口或重复终止服务。
- 启动失败不会归因于处于关闭状态的 MTP、视觉或思考能力；只有用户实际启用且配置有效的能力进入启动参数。

## 模型与文件边界

- Dense/MoE 类型只在新模型添加时识别一次；未知结果不猜测，类型变更重建配置而不复用跨类型参数。
- 思考档位、外置 MTP 和视觉模块必须通过显式检测或隔离加载验证；失败不会污染正式 Profile。
- 辅助 GGUF/mmproj 不作为独立聊天模型自动登记；下载完成也不会自动关联主模型。
- 主模型下载成功必须能从 llama 原生缓存或 GGUF 结构解析出真实文件；已管理模型会在扫描和自动登记时去重。
- “从列表中移除”不删除用户模型数据；外部删除的模型只标记不可用，用户可移除旧配置或重新添加重建。
- 原生缓存删除仍受 llama `can_remove` 和 Launcher 下载来源双重约束，与模型管理列表移除是两个独立操作。

## 网络、进程与隐私

- Desktop-facing 服务只监听回环地址并公开最小路由；认证、Cookie、账户/组织/项目 Header 不进入 llama.cpp。
- MTP、视觉和思考能力验证使用临时隔离 Router，具有有限超时和清理路径，不复用正式运行配置写入实验结果。
- Agent 继续验证协议、PID、路径、启动时间和心跳；llama 进程由创建它的 Agent 通过 Windows Job Object 管理。
- 前台状态监控降频，后台暂停；托盘菜单和状态提示仅在用户请求时刷新，不新增常驻高频轮询。
- 诊断日志不应包含 Prompt、图片正文、摘要正文、认证凭据、模型名称或任务 ID。

## 仍需真机覆盖的边界

- 不同 llama.cpp 版本对 MTP、MTMD/mmproj、Router 下载和思考档位元数据的实现存在差异，应以当前 Runtime 的实际返回为准。
- CUDA 是主要已验证后端；Vulkan、ROCm、多 GPU、低显存与 SSD 分层加载需要更多硬件组合测试。
- 在线漏洞审计依赖 NuGet 官方索引；离线测试包如果使用 `-SkipDependencyAudit`，`BUILD-INFO.txt` 会明确记录，不能冒充完成在线审计。
- 自签名 Authenticode 只能证明相同私钥持有者的发布连续性和签名后完整性，不构成第三方身份背书。

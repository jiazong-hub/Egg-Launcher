## 修复内容

| 问题 | 实施方式 | 验证重点 |
| --- | --- | --- |
| A01 运行文件回滚覆盖用户文件 | Agent 生成 BAT / Router preset / Catalog 使用仅生成文件的事务范围，不捕获用户 JSON、登记、模板；普通事务默认不包含用户 JSON，实际参数写入者显式选择纳入 | 注入写入失败后生成物恢复；外部修改的 JSON、登记、模板保留；删除 JSON 不会复活；实际参数保存失败仍能回滚 |
| A02 缓存设置覆盖后台端口 | 新增 SettingsMutationCoordinator，前台普通偏好修改与模式切换、恢复、端口迁移共用现有模式锁；锁内读取最新设置、执行字段修改、保存 | 迁移后的端口不被普通偏好覆盖；并发偏好不互相丢失；持锁迁移结束后更新读取最新值 |
| A03 前后台启动准入不同 | 将滚动证明和 Runtime 对 context-shift / keep 的既有选项检查移至共用 ModelStartupConfiguration；删除前台重复检查 | 主界面与后台新启动使用同一检查；缺失或否定证明时进程不启动；Runtime 无法确认选项时拒绝；已有会话仍使用已应用快照 |
| A04 控制监听因异常连接结束 | 单连接断开异常在本地处理后继续接收；命令读写设置 3 秒边界，保留 CurrentUserOnly | 客户端提前断开及连接后不发命令均不阻止下一次正常退出；现有强制结束备用流程未改变 |
| A05 载入/编辑静默关闭滚动 | 开关忠实载入 JSON；参数变化只失效显示的证明，不清除请求值；普通保存保留请求值；显示需重新验证，启动统一拦截 | 载入、保存、修改其他参数后请求值仍为 true；无法检测时也能保存其他模型的参数；已选开启但不受支持时仍允许用户关闭 |
| A06 错误续传区间 | 追加前检查 Content-Range 的单位、起点、区间及已知总长、Content-Length；完成时核对实际区间长度和总长；超长 partial 从头下载 | 正常续传、服务器改为完整 200、错误起点/总长/长度/缺少区间、截断内容、未知文件大小时的响应总长 |
| A07 外挂下载无限等待 | 响应建立默认 90 秒超时；每次等待新数据默认 2 分钟空闲超时；新数据到达后重新计时；超时显示重试提示 | 等待响应和无数据接收均能结束；用户取消保持取消语义；持续慢速传输不受固定总时长限制 |
| A08 无配置草稿继承旧参数 | 不可载入、缺失、损坏或未初始化配置均使用现有默认草稿构造方法，不沿用登记残留的旧运行参数 | 缺失/损坏 JSON 显示未载入与 16K 默认草稿；打开、取消不写文件；预选路径不会自动替换，JSON 不会自动恢复 |

只对已有上下文滚动证明及 Runtime 选项做准入检查，没有把读取帮助选项扩大为模型推理检测。参数保存不以滚动证明有效为必要条件；不满足条件的请求只能保存，不能绕过新启动检查。

续传增加的是基础协议检查，没有引入远端文件版本追踪或额外的全文件哈希体系；协议检查不代表对文件内容做完整性担保。资源仍沿用现有登记与验证流程。

## 复审关注点

- 设置更新入口逐一核对：模式切换、恢复及端口迁移继续持有原模式锁；前台偏好通过统一入口加入同一边界。锁不下沉到 LoadAsync / SaveAsync，避免这些方法在已有事务内重复加锁。
- Agent 只有重新读取预选配置的新启动使用共用准入；客户端运行时仍读取内存/已应用快照。已有“删除 JSON 后恢复运行会话”的回归继续通过。
- 运行生成事务只快照生成物；实际参数写入事务显式包含配置，保留原来保存失败后的回滚行为。模型移除事务继续不包含用户配置和共享模板。
- 普通保存不会触发模型验证。全局禁止检测时，检测按钮禁用且检测方法再次检查；不阻止其他未运行模型的普通编辑、载入与保存。
- 下载响应与文件流均释放；用户取消不会被转成超时。下载失败不发布目标文件，保留可续传的未完成数据。没有为大文件设置固定总下载时限。
- 没有修改 A09 使用旧 ConfigurationError 展示预选名称的逻辑；也没有因载入文件而替用户改变预选。

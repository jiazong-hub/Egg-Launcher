## 范围与结论

本次对模型信息迁移、四个管理按钮顺序及显示名称独立保存进行了源码自审、自动化回归和隔离 WPF 检查。本次范围内未发现剩余阻塞问题，可以提供开发测试包。这是本次实现自审，不是独立第三方审计。

## 数据与界面规则

- 模型管理五个选项卡顺序为模型信息、模型类型、模板管理、MTP 文件管理、视觉模块管理，默认打开模型信息。参数页仅保留运行设置。
- 本地模型列表下方删除“详情”，四个按钮严格按编辑运行参数、模型管理、显示/隐藏、从列表中移除排列。首页模式卡片点击名称打开详情的入口保留。
- 模型信息展示模型静态资料；文件名及完整路径从实际主文件路径取得，均只读。不展示 Context、GPU、KV 或取决于 JSON 的能力开关。主文件大小回退会标明“仅主文件”，不会冒充所有分片总和。
- DisplayName 是展示字段。保存名称直接读取最新登记，只原子更新此字段并保留未知元数据，不调用配置保存/初始化逻辑。ID、Alias、模型路径、配置目录、预选、资源证明和所有已有配置文件保持原样。
- 配置缺失、损坏或类型失配时仍可查看模型信息或保存名称，不自动修复配置。运行、检测、下载限制沿用原管理规则。

## 审查重点与处理

1. **旧参数页名称依赖**：删除信息控件、名称采集和相关编辑事件分支；保存参数仍绑定登记元数据。最新名称在保存/载入前读取，过期参数窗口无法通过应用恢复旧名称。
2. **同名及随意命名**：名称可包含空格、中文及文件路径不支持的普通字符，不作为文件路径或身份使用。不同模型允许同名；空白和控制字符拒绝保存。
3. **外部编辑**：登记名称已被其他操作改动时拒绝过期保存；提交前再次检查服务状态和原内容摘要，避免覆盖检测到的外部修改。没有宣称能够锁住资源管理器或任意第三方写入。
4. **界面同步与草稿隔离**：保存后刷新列表、模式卡片及管理窗口标题；取消名称草稿不落盘；名称保存不丢弃另一个类型页尚未保存的选择。
5. **真实操作对象**：从列表移除的确认框附实际文件名和完整路径，内部标识及既有移除逻辑保持不变。

# 资源重新检测实施与审查（2026-10-19）

> 0.9.9 发布归档（2026-10-20）：本文保留此阶段实现和当时检查数量，不作为当前发布状态或完整硬件验收的声明。当前操作以[用户指南](user-guide.md)、[实现说明](development-0.9.9.md)和[发布检查](release-checks-0.9.9.md)为准。

## 修改范围

- 模型管理的模板、外置 MTP、视觉资源行增加“重新检测”，对有效、失效及旧配置中尚未登记的原文件均可执行，不弹文件选择器。
- 旧引用仅从当前模型配置目录只读发现，按种类及实际路径去重；不信任 JSON 能力标志，不登记未经检测的能力，不能读取的文件有提示。打开及重新激活窗口时扫描，不在两秒状态刷新中反复读取全部 JSON。
- 模板沿用原生渲染，复查内置模板也不会自动生成新模板。外置 MTP 沿用联合加载与极短 `/completion`；视觉仍为 GGUF 元数据识别及运行库选项检查。内置 MTP 沿用正式启动确认。
- MTP 使用隔离临时配置，保留模型与草稿的加载设置，排除思考、视觉、聊天模板、n-gram 和自定参数等无关要求；视觉证据不再携带所选聊天模板依赖。没有新增检测协议。

## 记录与安全边界

1. 成功：验证依据未改变、模型与资源路径匹配、运行状态仍允许时更新原登记。原 JSON、启动预选、源模板、外挂文件及其他能力登记保持不变。
2. 明确拒绝：清除对应旧证明，并在资源记录标记 `ValidationRejected`。模板清除模板签名，MTP/视觉清除各自证明签名，旧格式读取方也不能把外部资源继续视为已验证。对匹配的旧模板缓存按需清理。
3. 未完成：用户取消、取消令牌、超时、服务忙、服务启动失败、检测接口不可用和运行状态变化不主动清除旧证明；旧证明是否仍有效继续按指纹判断。不把所有进程异常都认定为文件不兼容。
4. 内置模板通常不强制要求历史证明，但已经明确渲染失败的内置模板不能再静默启动；成功复查移除拒绝标记。关闭 Jinja 或选择另一可用模板不受该拒绝影响。
5. 文件缺失不能检测；检测前后依据改变不能登记。改名或移动不自动改写 JSON。移除仍要求先解除所有配置引用，未注册的发现行不提供“移除登记”。
6. 运行中检测限制、忙碌状态、进程及临时文件清理复用原流程。OpenAI 配置写入、恢复、认证和正常推理的参数生成流程未作本轮改动。

## 日志

复用现有 `DiagnosticJournal`。`resource_recheck` 简易日志记录种类、文件名、阶段结果及原因分类；详细模式补充阶段、耗时与异常栈。旧配置读取问题记录 `resource_reference_discovery`，不转储配置或模板正文。日志不可用不会改变检测结果。

## 审查与验证

审查覆盖行内回调绑定、路径保护、旧引用扫描、成功替换、拒绝失效、取消保留、运行中限制、模板复查不生成文件、内置模板启动拦截及恢复、其他能力记录和配置不变。未发现本轮引入的严重问题。

自动化与打包门禁结果记录在 `artifacts/resource-recheck-20261019` 及对应测试包构建信息中。全量测试 843 项通过，新增 28 项；Release 构建零警告、零错误，格式和差异检查通过。WPF 界面检查通过 544 项断言，覆盖中英文、明暗主题及 860/640 宽度。界面截图已检查行内按钮、窄窗口和滚动布局。

测试使用隔离文件、模拟的验证成功/拒绝结果及真实 WPF 控件，没有加载真实模型，没有修改正在使用的 Codex 配置。MTP 实际联合加载、模板原生渲染和真实视觉 GGUF 仍需测试机实测；接口不可用或资源不足属于未完成，不能据此认证兼容性。

## 重点审查

1. JSON→页面→JSON 保留数值、默认状态、接收者、顺序、无值开关；不会以字典覆盖重复行。
2. 保存、应用、另存共用严格检查，固定/自动参数、已知别名、相反开关及 Codex 父子键冲突均阻止写入，旧文件允许载入修正。
3. Router preset 与 BAT 采用同一组功能参数；短命令前缀保留。对 INI 注释字符和无法表达的值在保存时拒绝，BAT 尾随反斜线正确转义。
4. 不再将所有 Codex 字段按固定列表处理：动态字段持久化进入事务和恢复记录。A→B 的新字段、移除字段、异常中断和端点更新仍保留原始在线基准。
5. 修改 TOML 叶字段保留兄弟项、注释与认证文件；外部修改冲突及不支持的 TOML 结构在写入前停止。
6. 能力检测不执行实验性自定参数；自定 Codex 参数不让无关的上下文滚动记录失效。
7. 详细日志与简易日志均覆盖新增功能的关键阶段，新增结构化事件不转储任意自定参数值；原生输出继续使用原有记录和脱敏规则。

## 保留边界

- 实验参数的实际支持与效果依赖接收程序；不保证未来未知别名全部可识别。
- Codex 数组表路径不开放，封闭内联表不能安全新增字段时停止；同一次本地事务不自动转换父子键结构。
- 手工修改 JSON 可绕过保存检查，但不能绕过生成文件/配置事务的必要安全保护。
- 尚未进行真实模型的推理、性能、显存占用及测试机安装/升级/卸载验收。本次为源码与隔离测试审查，不代表正式发布验收完成。

## 后续修正：支持信息未知时新增参数过度置灰

稠密/MoE 专项核查发现：其他本地模型运行时，禁止执行检测会让运行库支持信息为空，新增固定参数误将其视为不支持，导致空白字段无法编辑。此前已发出的 Parameters-Test 安装包包含这一问题。

修复只调整 `ProfileEditorWindow.CustomParameters.cs` 的控件状态与悬浮说明：未知时允许编辑保存；明确不支持的空白字段保持禁用，已有值可清理；重新取得支持信息时恢复原说明。未改动模型类型绑定、保存语义、启动参数生成、检测入口或启动前校验。

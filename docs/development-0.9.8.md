# 0.9.8 实现与测试说明

发布日期：2026-10-18。本文前半部分说明最终实现，后半部分保留分阶段修改与当时的测试数量，不能将早期状态当作最终结果。当前操作以[用户指南](user-guide.md)为准，最终门禁及用户反馈见[发布检查](release-checks-0.9.8.md)。

## 使用方式

首页设置卡片增加 GitHub 项目主页按钮，位于语言切换左侧。

首页启动卡片右上角增加认证切换按钮，沿用卡片角落按钮的尺寸与交互。钥匙图标表示“本地模式使用 OpenAI 认证”：强调色钥匙为开启，带斜线的普通色钥匙为关闭。新安装及旧设置缺少字段时均默认关闭（`false`）。该全局设置保存在启动器 `settings.json` 的 `LocalRequiresOpenAiAuth`，不写入模型参数 JSON；下次启动本地模式时传入 Codex Provider 的 `requires_openai_auth`。客户端、本地服务运行或启动器忙碌时禁止切换，复用现有运行状态判断和刷新流程。保存开关不立即修改 `config.toml`，不修改登录凭据；切回在线模式仍恢复原配置并保留开关偏好。用户已实测反馈关闭认证后，本地模式不再显示额度和账户相关信息，仍可查阅在线项目；这不改变跨 Provider 原任务续聊边界。

本地模型管理通过“模型管理”窗口提供模型信息、模型类型、模板管理、MTP 文件管理、视觉模块管理。生成兼容模板、添加模板、加载外置 MTP 和加载视觉模块集中在该窗口内。这些操作登记资源和检测记录，不替换已保存配置的选择，也不启动正式会话。生成的兼容模板可以作为该模型以后初始化配置时的默认来源；已有配置不被覆盖。

“从列表中移除”只清理模型登记、列表记录、匹配的模型启动预选和启动器生成的 BAT，保留全部参数 JSON、模板、外挂和能力检测记录。若它仍是当前已应用的本地模型，须先实际切换到在线模式或另一个本地模型；只改变启动预选、仅关闭客户端或停止服务都不解除这一限制。移除其他模型不会切换或修改当前正在使用的模式和模型。

“生成兼容模板”的悬浮说明为“检查当前模型的聊天模板，按需生成兼容模板。”；“添加模板”为“选择已有的聊天模板，检查通过后加入当前模型的模板列表。”。两者提供中英文说明，首次悬停约 500 毫秒后显示，沿用已有提示样式。

“添加模板”的默认位置和导航根目录统一为 `scripts/templates`，只接受该目录直属的 `.jinja` 文件，不含子目录。模型生成模板、临时检测模板也使用此目录。添加、登记、下拉可选记录、保存及启动生成均检查这一范围，目录链接不能绕过约束；GGUF 内置模板不受外部文件目录限制。

已有目录外模板不会自动搬移或删除。旧登记和 JSON 保留原选择供修正，但该模板不再作为可用资源或启动依据；将模板放入 `scripts/templates`、重新添加检查后，在原 JSON 中重新选择并保存或应用即可。

参数页增加“模板设置”，位于基础参数和思考设置之间，包含 Jinja 开关和聊天模板下拉选择。视觉和 MTP 页面分别选择模型已登记且依据有效的资源。选择资源不自动开启功能，关闭功能保留选择。Jinja 关闭时不传递外部模板，但保留选择偏好。

视觉下拉菜单不再按当前 JSON 的聊天模板筛掉有效资源；选择后复用仍有效的元数据识别记录，允许开启开关。内置视觉和未选择状态分别处理，保存／载入保持每套 JSON 的选择。本次不增加视觉加载或图片验证，原始识别依据失效及 Runtime 不支持时仍拦截。详见 [视觉开关修复审查](vision-switch-review-20261018.md)。

页面右上角分别显示“载入配置”和“启动配置”。两行采用相同固定宽高、左对齐和独立行间距，右边缘与参数卡片区域对齐；名称隐藏 `.json` 后缀，超出显示宽度时末尾省略。未保存状态以独立的 `*` 标记显示，悬停可查看完整路径，点击定位文件；实际文件名和路径不变。

| 操作 | 文件与预选行为 |
| --- | --- |
| 保存为新配置 | 在当前模型专属配置目录选择名称；成功后编辑新文件，不改变预选 |
| 保存 | 写回当前载入文件，成功后关闭窗口，不改变预选路径 |
| 应用 | 保存参数并设为此模型的配置预选；窗口保持打开，不启动模型 |
| 取消 | 放弃尚未保存的修改；不撤销已经成功的保存、另存、应用或独立检测 |
| 载入配置 | 从当前模型专属配置目录选择 JSON；替换完整编辑状态，不改变预选 |

五个按钮均有中英文功能提示，首次悬停约 500 毫秒后显示，沿用已有提示样式。“取消”直接关闭页面并放弃未保存的编辑，不弹出保存询问，也不回滚此前已完成的保存或应用；窗口右上角关闭操作仍保留未保存提示。文件正在保存期间，取消不会中断已开始的写入。

如果载入和预选都是 A，保存 A 后，下次自然读取更新后的 A。配置预选与首页/模式页的模型启动预选分别维护。

首次初始化自动创建每模型独立的 `scripts/profiles/configurations/<模型ID>/未命名.json`。保存和载入对话框默认位置及导航根目录都是该模型的专属配置目录。保存、另存、载入及新启动仅接受该目录下直接存放的 JSON，不包含子目录；其他位置、其他模型目录及通过目录链接跳转的位置均不可用。目录名继续采用现有模型 ID，不随显示名称改变。用户配置使用独立格式版本 1，内部模型参数 schema 继续为 13，与主模型绑定，其他模型的配置即使被复制到本目录也不能载入；旧版内部 Profile 由迁移流程转换，不与用户文件混合扫描。

此前测试版保存在其他位置的配置不会自动搬移或删除。请先在资源管理器中将所需 JSON 放入对应模型配置目录，再载入并应用；原目录外预选会显示不可用，新启动被阻止，现有运行快照不受影响。

## 数据与生效边界

诊断日志沿用原有“详细日志记录”开关：关闭时使用简易模式，保留关键操作结果、拦截和错误；开启时增加阶段、耗时和异常栈，只写入当时模式对应的文件。启动器界面操作写入同一日志目录下的 `launcher.concise.jsonl` / `launcher.full.jsonl`，Agent、代理及原生运行日志保留原用途，复用现有 JSONL 格式、脱敏与轮转组件。

新增记录覆盖配置载入、保存、另存、应用、卡片预选、用户触发的目录扫描、资源添加/检查/复用/移除、模型名称/类型/显示状态/列表移除，以及前后台启动、认证偏好、事务回滚、在线和卸载恢复。界面刷新、鼠标悬浮与参数输入不记录。认证日志区分缺字段默认值、已存设置、请求应用值及成功应用值；不把偏好当作当前客户端内存中的实际状态。各操作使用短小摘要及关联 ID，不输出完整参数 JSON、TOML、模板或任意异常消息。实施审查见 [诊断日志补齐审查](diagnostics-review-20261018.md)。

Router 日志的运行时版本改为优先解析 `llama-server --version`，产品版本和文件版本作为备用；记录版本来源，详细模式追加查询结果分类。每个 Agent 对当前路径、长度、修改时间均未变化的程序复用内存结果，端口重试、健康检查及异常重启不重复查询；程序变更后重新取值。不增加配置文件、不修改模型 JSON，查询超时或失败仍继续启动。实施审查见 [运行时版本日志修复审查](runtime-version-review-20261018.md)。

- 模型登记继续位于 `scripts/profiles/<模型ID>.json`，保留可信的模型身份、来源和配置预选。
- 资源及思考能力记录位于 `scripts/model-resources/<模型ID>.json`，不依赖某一配置文件才能复用。
- 用户 JSON 保存完整参数和资源选择。是否下发参数仍由原有 BAT、Router 和 Codex 生成规则决定。
- 资源记录同时检查具体主模型文件绑定，不能因友好 ID 被重新使用而继承另一主模型的结果。
- 检测方式沿用现有实现。视觉加载是元数据识别；模板检查是渲染检查；MTP 联合加载等保持各自已有范围。记录不扩大为所有组合或完整工具能力保证。
- 路径、文件名、文件内容特征、Runtime 或相关依据变化时，只使对应记录失效；不按时间过期。内置 MTP 继续沿用已有候选/原生加载准入规则。
- 当前失效资源可以作为不可用占位显示，不能静默换成另一附件。已经启用但没有匹配依据的能力会阻止新启动，要求处理。
- 参数保存不生成运行文件。新启动时按预选文件读取快照，重新生成一套模型 BAT、全局 Catalog/Router preset，并通过原有事务应用 Codex 设置。
- 本次已应用运行快照单独保存在启动器数据目录的 `generated/applied-local-run.json`；它参与模式配置生成物的回滚，用于已有会话的后台恢复。
- 模型休眠唤醒、已有服务复用及已有会话恢复，不属于使用新配置的新启动。
- JSON 外部改名、移动或删除不影响现有运行；新启动不能使用旧生成物回退。预选缺失显示“无”，不自动选择其他文件；可在卡片菜单选择有效配置，或在参数页载入并应用。
- 外部并发修改通过读取内容摘要识别，普通保存拒绝覆盖过期编辑；可重新载入或明确另存。
- 不创建用户配置 `.bak`，不从旧 `.bak` 自动重建配置。遗留文件不主动删除。原子写入、事务保护及 OpenAI 恢复记录继续保留。
- 本地服务运行期间禁止能力检测，正在运行模型不能打开参数页；其他未运行模型可编辑、保存、载入和预选。
- 参数页检测期间禁止载入其他配置或应用配置；检测结束或取消并清理完成后恢复操作，避免异步结果与另一份配置混合。

## 建议真机验收

1. 对同一模型保存 A、B 两份不同参数配置。载入 B、保存 B 后，预选仍为 A；应用 B 后才切换，窗口不关闭。
2. 分别选择已登记的模板、MTP 和视觉来源；不应自动启用，其他配置内容保持不变。相同有效依据不应重复检测。
3. 启动 B，核对原生参数和客户端目录；修改或删除 B 后，当前会话继续。停止本地服务后的下一次启动，读取新内容或如实报告文件缺失。
4. 本地 X 运行时编辑未运行 Y，应用 Y 的配置不应切换 X，也不应修改模型启动预选；各类检测不可执行。
5. 替换/改名附件或模板后核对失效提示；加载另一主模型的 JSON 应失败且保留原编辑对象。
6. 无论预选 JSON 是否存在，都检查切回在线模式及卸载恢复。

开发阶段测试包曾使用未提交工作树构建，提交 SHA 仅标识当时基线。正式发布从已提交源码重新构建；实际源码以 BUILD-INFO.txt 的提交、SourceTreeSha256 和包内清单共同核对。开发检查不能替代上述新版真机验收。

## 2026-10-16 模型移除范围修正

移除模型不再删除其引用的生成兼容模板。当前已应用模型的移除按钮禁用，禁用时仍可悬停查看切换要求；点击入口和底层移除操作同样检查已应用状态。成功切换到在线模式或另一个本地模型后即可移除原模型，单纯预选其他模式不算切换。

清理通过只覆盖模型登记、旧登记备份、缺失标记及 BAT 的事务进行。设置写入失败时恢复这些文件；参数 JSON、模板和资源记录不进入移除事务，失败回滚不会覆盖期间发生的外部编辑。无法确认归属的 BAT 会阻止移除。能力记录保留，重新使用时仍须指纹有效；重新添加不自动猜测并恢复之前的 JSON 预选，也不覆盖旧配置。

自动化回归扩展为 492 项，包括实际应用与预选的区别、在线及其他本地模型下移除、保留全部资源、异常回滚、配置缺失和重新添加。使用临时 Runtime 和设置文件，未执行用户真实模型移除或模式切换。记录见 `artifacts/implementation-0.9.8/model-removal-tests-20261016.log`，中英文提示预览位于 `ui-model-removal-20261016`，最终构建及打包门禁见同级 `model-removal-package-20261016.log`。

## 2026-10-16 模板与外挂资源管理

- 本地模型管理增加“模型管理”入口，打开所选模型的模态窗口。模板管理、MTP 文件管理、视觉模块管理三个选项卡集中承接原有四个添加/生成入口。
- 列表按资源路径合并展示，完整路径通过悬停显示；内置能力是固定信息项，不提供文件移除。缺失、失效的外置记录保留在管理列表供查看和清理，参数下拉只提供适用的有效记录。
- 重复添加先检查当前模型、规范化路径及原有验证依据；有效则提示已添加并跳过重复检测。视觉继续按模板依据匹配。兼容模板按当前生成内容及有效检查记录复用，不覆盖或改选已有 JSON。
- 移除只更新当前模型的资源登记，不删除硬盘文件，不影响其他模型登记。检查模型目录内全部直属 JSON，关闭功能但保留选择也属于引用；配置损坏、身份不匹配或无法读取时阻止移除。移除默认模板登记时清除默认标记。

## 范围

模板规则、参数页面提示、隔离渲染检查、明确模板异常分类。
不改变在线配置、沙箱事务、跨模式历史查阅、请求正文转发或正式推理参数。
Profile schema 仍为 11，验证记录使用独立的模型专用 sidecar。

## 实现

- 统一 `IChatTemplateCompatibilityRule`：规则编号、版本、工具标记、结构检测与局部修复。
- 当前注册 `qwen-strict-system:2` 与 `unsloth-merged-system:1`。
- 未命中与有歧义均不自动生成。未来新增系列只需新增规则、注册及测试样本；
  文件管理、验证、回退、UI 共用已有流程。修改规则行为必须提高版本号。
- 保留开头消息处理，在原消息位置输出后续系统／开发者消息；
  Qwen 原始结构还允许开头 developer 进入已有的系统消息处理。
  保留工具调用、工具结果、思考输出及模型特殊标记。
- 添加模型不再静默启用未验证模板。启动前发现支持规则时询问用户；
  参数页面提供检测与生成、打开目录、恢复内置模板。
- 生成的内置备份与兼容文件分开，保留源哈希、规则版本及文件内容哈希。
  用户指定文件不自动改写；被编辑的生成文件不覆盖。
- 隔离 Router 使用 4K context、2K reserve、1K tool limit、单槽位，
  关闭 MTP、视觉及滚动，只执行 `/apply-template`，不执行推理。
  检查通过才保存新模板路径。检查临时设置不写回用户参数。
- 六组原生检查涵盖首个 developer、连续开头 system/developer、后续同类消息、
  多轮以及工具调用和结果回传。检查内容保留、唯一性和先后顺序。
- 验证签名包含模型路径/大小/修改时间、模板哈希、Runtime 大小/修改时间、
  规则集合版本与 Jinja 开关。结果变化显示过期；已有手选模板不会静默替换。
- 渲染成功始终显示“实际对话待验证”，不宣称 Codex 工具执行、压缩或 GPU 稳定性通过。
- 原明确 Jinja 消息位置错误新增分类，原 HTTP 状态和正文保持透传。
  前台按当前 Agent 会话提示一次，不自动重启或热替换模板。

## 审查发现与修正

1. 取消编辑可能影响已保存配置引用的模板：编辑器生成独立命名文件，
   仅填入编辑框；保存前不替换旧引用文件。取消编辑允许保留未启用文件。
2. 生成后验证或保存失败可能留下半完成文件：事务覆盖内置备份、验证记录、
   默认兼容文件和编辑器独立文件；失败时恢复原文件。
3. 隔离检查工具额度不能等于 reserve：改为 1K < 2K < 4K，
   实际 Router 检查已通过。
4. 普通 HTTP 500 不能证明模板错误：仅明确 Jinja 错误判为渲染失败；
   不支持接口、资源或普通服务错误均显示检查未完成。
5. 原模板或 Runtime 在检查期间变化会使验证失真：前后核对签名与模板内容，
   不保存已经过期的结果。
6. 原归属标记不能证明内容未被编辑：新文件核对内容哈希，
   旧文件只有从同一内置模板重建后完全一致才允许覆盖。
7. 检测与现有工作冲突：客户端、同一 Runtime 的原生服务或下载任务存在时拒绝隔离检查；
   原生进程生命周期继续使用现有 Manager、独占 Runtime 锁及退出清理。

## 测试机验收

1. 安装测试包，保持详细日志开启。关闭客户端并停止原 Local 服务
   （可先切回在线模式），再打开 27B 模型参数。
2. 确认 Jinja 开启。路径空时应显示内置模板及已支持的不兼容规则。
3. 点击“检测与生成”，同意临时加载。成功后应出现独立兼容文件路径，
   状态为渲染检查通过；点击保存，再启动 Local。
4. 测试“你好”、多轮对话和只读工具调用，确认没有原消息位置异常。
5. 测试取消检测、取消参数保存、恢复内置模板，确认配置不被意外覆盖。
6. 9B 原有兼容文件继续工作，用户指定模板路径保持原样。
7. 分别验证在线启动及跨模式历史查阅；最后单独测试 Vulkan 压缩。

恢复内置模板只清空参数页路径，需要保存才能生效；文件保留供回退。
若下次启动再次发现已支持的不兼容规则，会询问是否生成，用户可以拒绝。

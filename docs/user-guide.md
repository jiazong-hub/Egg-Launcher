# Egg Launcher 0.9.7 用户功能说明

本文说明 0.9.7 的功能，发布于 2026-10-07。启动器是 llama.cpp 与 ChatGPT Desktop 之间的管理外壳，不重复实现推理、KV Cache、模型调度或语义摘要。沙箱设置仍为 beta，实测范围与已知限制见[版本说明](release-notes-0.9.7.md)及[正式检查记录](release-checks-0.9.7.md)。

## 1. 模式与数据边界

- `OpenAI` 与 `Local LLM` 互斥；切换前必须完全关闭 ChatGPT Desktop。
- 关闭启动器或客户端不会自动切回 OpenAI；当前模式和所选本地模型会保留。
- 用户可在 ChatGPT 关闭后直接执行 Local 模型 A → B，不必先回到 OpenAI。
- 项目、任务历史和开发上下文共用；Provider、可见模型列表和请求目标隔离。
- Local 复用 ChatGPT Desktop 的账户外壳以显示原生项目与历史，因此仍可能看到官方账户名称或额度提示。这不代表请求发送到 OpenAI。
- 本地代理会在请求进入 llama.cpp 前移除 Authorization、Cookie 和账户相关 Header。
- 切回 OpenAI 时恢复进入 Local 前的官方模型、思考强度、详细程度、服务层级、上下文和权限字段。
- 切回 OpenAI 后，启动器保留一个未激活的本地历史 Provider 定义，供客户端识别和查阅旧 Local 对话；当前官方模型仍按官方路由运行。跨模式支持查阅历史；原任务跨 Provider 续聊方案已放弃，请在目标模式新建任务继续开发。

## 2. 首页

### 界面语言

- 默认跟随 Windows 显示语言：中文系统使用中文，其他系统语言使用英文；只在启动时读取，不进行后台轮询。
- 语言按钮仍显示当前实际语言 `ZH` 或 `EN`。单击会切换并固定为中文或英文；右键选择“跟随 Windows 显示语言”可恢复自动模式。
- 从旧版本升级时，原有中文/英文设置会迁移为“跟随系统”。Windows 显示语言改变后，重启 Egg Launcher 即可应用。

### 外观与提示

- 首页设置卡片右上角提供语言和深色/浅色切换；主题、语言与主窗口状态持久化保存。
- 浅色与深色模式使用同一布局和功能层级，只调整背景、卡片、边框、文字和强调色。
- 底部提示条可手动关闭，并在显示约 10 秒后自动消失；新的提示会替换旧提示并重新计时。
- 页面切换、选项卡和弹窗使用短时轻量动画；功能卡片不使用持续悬停位移，避免布局抖动和复选框闪烁。

### 当前持久化模式

- `OpenAI`：确认后恢复官方 Provider 配置并启动 ChatGPT Desktop。
- `Local LLM`：进入本地模型选择，不会仅因点选标签而立刻改写配置。
- 当前模式显示来自持久化配置，不等同于某个进程此刻是否运行。

### 环境状态

- ChatGPT Desktop：运行中或已关闭。主窗口位于前台时低频刷新，最小化或隐藏后暂停；模型管理和托盘交互会按需读取一次最新状态。
- Launcher Agent：停止、运行、身份不匹配或异常。
- llama.cpp：停止、Router 就绪、模型已加载、模型已休眠或异常。
- llama 后端：显示 llama 当前报告的 CPU、CUDA、Vulkan、ROCm 等后端信息；无法证明时显示不可用，不根据显卡名称猜测。
- 运行模型：放在状态卡片最下方，显示当前实际配置的本地模型。
- 切换、保存和恢复期间显示忙碌状态并禁止重复操作。

### 后台启动与诊断

- `登录 Windows 时启动后台 Agent`：写入或移除当前用户 Run 项；不使用管理员服务。
- 启动项只允许指向可信固定目录中的同包 Agent；可被普通用户组或沙箱修改的路径会被拒绝。
- `打开诊断日志文件夹`：打开 `%LOCALAPPDATA%\ChatGPTLocalLauncher\logs`。

### 托盘

- 单击托盘图标打开或恢复主窗口；右键菜单依次提供打开 Egg Launcher、启动 ChatGPT、当前模式、切换模式和退出。
- “切换模式”子菜单与模式页面状态一致；不可用的模式或操作在托盘中同样禁用。
- 托盘状态提示按多行显示当前模式、ChatGPT、配置状态、llama 服务、llama 后端和运行模型。
- 菜单打开或请求状态提示时只刷新一次，不进行常驻后台轮询；语言切换后直接使用同一状态快照重新格式化。

## 3. 本地模型页

### llama.cpp Runtime

- `选择文件夹`：选择包含 llama.cpp 可执行文件的 Runtime 根目录。
- 探测内容：版本、Router、空闲休眠、Chat Template、metrics 和设备列表等能力。
- Local 模式或当前 Runtime 的服务运行时禁止更换 Runtime。
- 缺少必要目录时会询问是否创建；能力不足时显示具体诊断。
- `搜索并下载 GGUF（实验性）`：打开模型搜索与下载窗口。

### 扫描结果

- `扫描模型`：扫描 Runtime 的 `models` 目录。
- 支持单文件 GGUF 和完整多分片 GGUF；缺失分片会报告异常。
- `mmproj` 不作为独立主模型加入。
- `添加选中模型`：建立 Profile、BAT、Catalog 和 preset；不会加载模型或启动 ChatGPT。
- 首次添加后可选择调用 Runtime 的 `llama-fit-params`，应用前必须由用户确认。

### 已管理模型

- 模型列表显示所有已管理 Profile，并保留当前选中项。
- 名称前显示 `【Dense】`、`【MoE】` 或类型未指定；具备已确认能力时继续显示 `【Vision】`、`【MTP】`。能力标识表示可用，不表示已经开启。
- 新模型只在首次添加时读取元数据识别 Dense/MoE；旧 Profile 或无法识别的模型由用户手动指定，不在每次打开页面时重复扫描。
- 更改已确定的模型类型会重建该模型参数配置，避免 Dense/MoE 参数混用；模型文件保持不变。
- 摘要显示名称、别名、来源、路径、总大小、分片、当前参数和专用默认值。模型文件被外部删除后条目变灰并提示不可用。
- `编辑运行参数`：模型类型明确且文件存在时打开参数窗口。
- 保存参数会同步写入该模型的 JSON 和 BAT；若它是当前配置的 Local 模型，也会立即同步更新 Router preset、本地模型 Catalog，以及 Codex 受管理配置与恢复记录。保存不会启动或重新加载 llama.cpp；当前 Local 模型须先关闭客户端并停止 Agent 与当前 Runtime 的 llama 服务才能编辑。编辑其他模型不会覆盖当前 Local 模型的 preset/Catalog 或 Codex 配置。下次冷启动或切换到该模型时重新读取已保存参数，通过模式配置事务应用对应的 Context、压缩线、工具输出预算与沙箱设置。
- `模型类型`：指定或更改 Dense/MoE；更改既有类型前会说明配置重建影响。
- `由 llama 自动适配`：必须先切回 OpenAI，并停止当前 Runtime 的 llama 服务；展示原生建议后，可选择应用并保存为当前模型默认。
- `模型详情`：显示文件、来源、大小、分片、架构、参数量、训练上下文、模态与运行参数；部分信息仅在 llama 已运行且返回时可用。
- 思考能力检测位于各模型运行参数的“思考设置”页。
- `加载/移除外置 MTP`、`加载/取消视觉关联`：只改变当前模型的辅助能力关联，不删除辅助文件。
- `在模式卡片中显示/隐藏`：控制该模型是否出现在模式页面，不影响 Profile 和磁盘文件。
- 三个主页面共用连续收窄的侧栏，宽度在 292～82 个逻辑像素之间随窗口变化；Logo、留白和导航文字逐步调整，最后保留图标，并提供导航提示。模式卡片保持 390 的宽度与 14 的间距，空间不足时换行，单列不拉宽到 600。
- 首页与模型页保留原来的两列四卡片布局：仅当小屏工作区使可用内容宽度低于 700 个逻辑像素时转为单列，恢复两列时留有 24 的缓冲。小屏单列卡片区域最大宽度 680，启动按钮居中并保持 220 的常规宽度（空间不足时受父容器约束），不随卡片横向拉长。标题、说明和开关文字可以换行，标题操作按钮占独立列。
- 侧栏在 1120 的窗口宽度下保留 220 的宽度，继续显示品牌文字、签名和四列性能环；继续缩窄时逐步调整布局。侧栏宽度低于 220 时性能环改为两列，更窄时关键运行信息移至主内容底部状态栏，仍使用原有数据更新。
- 主窗口设计最小尺寸为 960 × 640 个逻辑像素（会随 Windows 缩放比例换算为屏幕像素）。工作区更小时按当前显示器放宽下限，主内容和侧栏均可纵向滚动；移回大屏后恢复设计下限。最小尺寸同时作用于 WPF 布局与原生窗口拖动限制。
- `从列表中移除`：删除 Launcher Profile 和受管生成物，不删除主模型、MTP、mmproj 或 llama 缓存数据。当前正在运行的模型不能移除；若只是当前配置模型，会先给出切回 OpenAI 的建议与确认。
- 同一路径模型再次添加时会重建 Profile；扫描和下载自动登记均排除已经管理的模型，避免二次添加。
- `切换并启动`：确认模型和上下文后写入 Local 配置，启动 Agent/Router，验证 Responses 路径，再启动 ChatGPT Desktop。
- 扫描结果和已管理模型列表可各自滚动；列表到达边界后，继续滚轮会滚动外层页面。

## 4. 模型参数窗口

### 长对话参数联动

- Context 为 C、安全余量为 R、显式工具结果上限为 T。余量范围为 `max(1,024, floor(C/11)+1)` 到 `C−1,024`，工具上限范围为 `1,024` 到 `R−1`；自动压缩线始终为 `C−R`。
- `C < 11R` 是按约 10% 摘要空间制定的经验保护，不保证实际压缩输入不越过触发线，也不限制模型生成命令参数。
- 修改 Context 或余量会更新后续参数的快捷选项、范围和有效性；输入整数 tokens 或 K 均可，快捷选项不再固定止于 32K/24K。当前输入不会被自动改写，非法关系会提示并禁用两个保存入口。
- “自动（模型默认）”无法确定本次上下文容量，需要选择明确的 Context 后保存长对话配置。“沿用 Codex 设置”保留继承语义；当前界面不能可靠确认客户端的最终继承值，会显示未知提示，允许保存。
- 显式工具预算接近余量、余量超过上下文一半时显示提醒。旧配置原值保留，用户修正后再保存；模型配置校验及启动前配置事务使用同一套数值关系。模型目录的 `truncation_policy` 策略本次不变。

窗口按顺序使用七个选项卡：`基础参数`、`思考设置`、`视觉模块`、`MTP 推测解码`、`高级参数`、`沙箱设置`、`模型信息`。各页内容背景使用统一宽度，每个选项卡独立滚动；底部恢复、取消、保存与保存为默认按钮保持固定，并与内容背景左侧对齐。

参数窗口内的文本输入框与下拉框统一使用 5 像素圆角、固定 32 像素单行高度、12 号常规字重，以及相同的文字留白、边框和聚焦状态。可编辑下拉框的内部文本区域使用独立无边框模板，不叠加外框或额外留白。可编辑下拉框既可选择预设，也可直接键入自定义值。视觉、MTP 与高级参数按可见字段排列为等宽两列，列间距 20 像素、行间距 12 像素；隐藏参数后自动重新排列，标题换行时仍保持输入控件对齐。正文说明使用 12 号常规字重，与选项卡标题样式分离；多行输入可继续扩展高度，沙箱动态路径行使用相同输入样式。样式仅作用于此窗口。

### 基础参数

- 显示名称：可编辑。
- 别名与模型文件：只读。
- Context：4K、8K、16K、32K、64K、80K、128K，对应 llama.cpp `-c`。
- 压缩安全余量保留常用预设，并可直接输入自定义整数 tokens 或 K 值（1K=1,024 tokens）；不再以 32K 封顶。至少为 1,024 tokens 且严格小于有效 Context。
- 页面顶部的“长对话与上下文”集中显示 Context、压缩安全余量、Codex 压缩线、工具结果历史上限与上下文滚动。
- Codex 压缩线：`Context - 压缩安全余量`，随设置变化显示；安全余量不是输出 token 上限。
- Codex SSE 空闲等待时间按模型保存：可选沿用 Codex 默认，或以 5 分钟步进设置正整数分钟；下拉预设到 120 分钟，也可输入更大值（最大 35,790 分钟）。当前 Local 模型点击保存后立即同步 `config.toml` 本地 Provider 的 `stream_idle_timeout_ms` 及恢复记录，选择默认时移除该覆盖；服务读取新值仍需下一次启动。此项用于普通回答及上下文压缩，不会加快模型处理，也不生成 llama.cpp 命令参数。切回在线模式使用原有配置。
- 工具结果历史上限可以直接输入自定义值，不再以 24K 封顶。例如安全余量 24K 时可以输入 20K 或 20480。至少为 1,024 tokens，且严格小于安全余量；单个结果上限不会限制整轮命令数量，也不限制模型生成命令参数。该项对应 Codex `tool_output_token_limit`：默认沿用用户已有的 Codex 设置；按模型选择具体值时只限制单次工具结果写入历史的 token 数，不限制模型单次回答，且该值须小于压缩安全余量。切回 OpenAI 时恢复原有配置。
- `上下文滚动`：双态开关，默认关闭。首次开启时临时加载当前配置，使用一个受控请求确认实际滚动，不以 `--help` 存在参数作为支持证据。未知或不支持时保持关闭并显示原因；提供重新检测入口。检测可能需要几分钟，会占用正常运行所需内存/显存；运行中的任务不会被停止，必须先关闭使用当前 Runtime 的服务。检测期间参数不可修改，底部可取消；临时进程会清理。
- 检测结果独立缓存于 Profile 目录的 `.context-shift-cache`，不会随模型默认参数复制。模型、Runtime 可执行文件/库、辅助文件、模板或运行参数改变后原结果失效；无结果的旧开启配置需要重新确认。安全余量与工具结果上限变化不影响缓存。只有取得实际滚动证据才允许保存开启状态。
- 保存更新 Router preset 与独立 BAT，下次启动模型生效。开启显式生成 `context-shift = true` / `--context-shift`，关闭显式生成 `no-context-shift = true` / `--no-context-shift`，不通过省略参数表示关闭。两个参数只生成其一。
- 正常运行时若 llama.cpp 报告滚动被禁用，Agent 记录 `context_shift_disabled`、更新能力缓存与运行状态；界面显示实际禁用原因，后续不能使用该缓存开启。日志另记录请求参数 `context_shift_requested` 与实际滚动 `context_shift_performed`。这是读取启动信息，不额外进行能力探测。
- llama.cpp 的上下文滚动发生在生成期间：当前上下文用量达到模型配置的 Context 上限时，llama.cpp 可丢弃较早的上下文并继续生成；触发依据是上下文总用量，不只是生成输出长度。滚动可能使模型遗忘指令、前文或工具内容。Codex 上下文压缩则会摘要并重建对话历史。滚动不修改 Codex 历史或压缩阈值、不生成摘要，也不保证下一条超出模型容量的 Codex 请求能够放入窗口。
- Context 低于 16K 时仅提示风险，不自动修改或阻止保存。
- GPU Offload：Auto、All、0（仅 CPU）。
- Flash Attention：Auto、On、Off。
- K/V Cache：F16、BF16、Q8_0、Q4_0、Q4_1、IQ4_NL、Q5_0、Q5_1、F32。
- Batch：Default、128、256、512、1024、2048。
- Micro Batch：Default、64、128、256、512。
- 并发 Slot：1、2、4。
- 空闲释放：30 秒、1 分钟、5 分钟、15 分钟、禁用。
- Jinja Chat Template：默认开启，留空使用 GGUF 内置模板；填写路径则使用指定模板。页面显示模板来源与验证状态。
- “检测与生成”：关闭客户端并停止同一 Runtime 的服务及下载后执行。支持已识别的 Qwen／Unsloth 严格消息规则，经过用户确认、局部适配和隔离渲染检查后才填写兼容模板路径；未命中或结构有歧义时不自动生成。
- “打开模板位置”用于查看模板文件；“恢复使用内置模板”清空路径，保存后生效，原文件保留。用户指定模板和被手工修改的生成文件不会被静默覆盖。
- 渲染检查通过不等于实际对话、工具调用或压缩已经验证。模板、模型或 Runtime 变化后，原验证可能与当前依据不一致。规则框架预留其他系列扩展，本版本不承诺兼容所有模型。
- 思考设置：顶部检测入口使用实际选定模板；模板信息与基础参数同步，只读显示。需要兼容模板时先在基础参数生成，再检测，生成文件保留。
- 原生思考开关与档位分别验证，证据不足显示未确认，不默认填中档。逐档验证渲染、无效值拒绝和 Responses 的完整实际提示词；验证通过才开放设置。只向 Codex 提供确认的独立档位及默认值，保留原始名称和大小写，不映射；定位与可信 Desktop 安装组件 SHA256 一致的缓存 CLI，使用其协议 schema 确认兼容性；无需独立安装 CLI。兼容性未确认或不支持时保留模型检测结果，并禁用聊天档位调节。模板内部别名只在详情列出。
- “反转档位显示顺序”默认关闭，按模型保存；关闭时沿用原始列表，开启时仅反转 Codex 目录排列，原始值、说明对应关系及默认档位不变。上方档位调节开关可用且开启时才能操作；关闭、不可用或检测中时置灰，保留反转偏好。保存后同步当前本地模型配置；已有且仍有效的验证无需重做。
- 完整提示词仅记录隔离检测的固定测试请求，检测结束清理临时目录。旧运行时未提供提示词记录能力时，Responses 传递保持未确认，不能用输入 token 数相同判定通过。
- 模板丢失时可进入参数页修复，不会自动改用其他模板。后台重启前检查思考验证指纹；依据不一致且 Codex 已关闭时同步清理受管理配置，Codex 正在运行时停止该次启动并提示关闭后重新保存或检测。取消或超时会保留结束提示及检测前设置。
- 用户可开启、关闭思考或沿用模板默认；默认未知时如实提示。“显示思考过程”默认关闭，位于“启用思考”下方；启用思考关闭、能力未确认或检测中时置灰并保留偏好。开启时通过兼容显示通道展示原始思考内容，不改变是否进行思考；已有历史不会自动补显示。思考与档位调节分别由对应能力验证约束，关闭思考不会关闭或禁用档位模块；实际是否应用档位由模型模板和运行时决定。
- 检测结果保存才应用，取消不写入。当前 Local 模型保存即同步受管理配置，使用中的模型须先停止才能编辑。模型、模板或运行时等验证依据变化后要求重新检测；仍准确匹配的旧 v4 记录可迁移，无需重测，启动时不自动检测。

### MTP 推测解码与视觉模块

- MTP 推测解码：默认关闭。主 GGUF 带有可识别的 NextN/MTP 层时会显示为内置来源；外置文件必须先在“本地模型管理”中选择，并通过 llama.cpp 的联合加载与极短推理验证。验证成功只建立关联，不会自动打开 MTP。
- MTP 常用参数：N Max、N Min、P Min、P Split 与后端采样；留空时不写入 Profile，继续使用 llama.cpp 默认值。
- 外部 MTP 可单独设置 GPU Offload、设备、K/V Cache 与线程数。外部文件不会作为独立聊天模型加入模型列表；移除关联也不会删除磁盘文件。
- “本地模型管理”会在模型类型后显示 `【MTP】`：内置 MTP 候选或已通过联合加载验证的外置 MTP 才会显示。取消外置关联，或外置文件被删除、替换后再次进入管理页，标识会自动撤销且 MTP 开关会关闭；此检查只在相关操作时执行，不进行后台轮询。
- Hugging Face 仓库中的 MTP 候选文件按单文件任务下载。下载成功后只保存到 Runtime `models` 的启动器受管理目录，不自动关联任何模型；用户需在“本地模型管理”中自行加载和验证。主模型下载成功后仍会自动添加到模型管理。
- 内置 MTP 在启用后的首次正式启动中由 llama.cpp 原生验证；外置 MTP 在建立关联前即完成隔离验证。主模型、辅助文件或 Runtime 变化后验证失效，普通 MTP 参数调整不会抹掉文件兼容性结果。
- 视觉模块位于“基础参数”和“MTP”之间。只有通过 llama.cpp `/models` 图片能力检查及真实 `input_image` 请求的配置才可开启，并在模型名前显示 `【Vision】`。
- 外置视觉模块使用与主模型匹配的 `mmproj` GGUF。“加载视觉模块”只建立当前模型的关联，不会把 mmproj 注册为聊天模型；取消关联不会删除文件。主模型、mmproj、Runtime/MTMD 库或 Chat Template 发生变化时，验证自动失效且开关关闭。
- Hugging Face 中识别出的 mmproj 以单文件任务下载到 `models\egg-launcher-vision`，不会自动关联模型。视觉参数留空时保持 llama.cpp 默认值，可选项包括投影器 GPU Offload、设备、图片 Min/Max Tokens 和 MTMD Batch Max Tokens。
- ChatGPT 仅在视觉功能已经验证并开启时看到 `text + image` 输入能力。本地代理只转发 `data:image/...` 图片，不代替客户端下载远程图片，也不接受 `file:`/HTTP(S) 图片引用。

### 高级参数与模型信息

- 高级参数包含 llama.cpp 支持但不属于常用基础项的运行参数；Dense 与 MoE 根据模型类型显示适用内容。
- `Context Checkpoints` 对应 llama.cpp `--ctx-checkpoints`：留空使用 Runtime 默认值，0 关闭检查点；关闭可能增加长前缀恢复时的预填充耗时，不改变 Codex 自动压缩阈值。
- `保留开头 token（--keep）` 位于高级参数，默认留空且不生成启动参数。需要先选定明确的 Context 数值；填写小于 Context 的非负整数后会写入当前模型的 Router preset 与独立 BAT。它在上下文滚动时保护开头的 token，同时减少可滚动空间。编辑与启动时都会确认当前 Runtime 支持此选项。
- MoE 可设置专家相关的 CPU/GPU 放置等参数；实际支持仍由当前 llama.cpp 构建和模型架构决定。
- 所有可选参数在用户没有调整时保持未设置，不会为了填满配置而覆盖 llama.cpp 默认值。
- 模型信息包含显示名称、Alias、模型文件和模型类型；Alias、文件与类型不在此页直接改写。
- `恢复此模型默认`：仅当当前模型已保存专用默认快照时可用。
- `保存`：保存当前 Profile。
- `保存并设为此模型默认`：保存并更新当前模型自己的默认快照，不影响其他模型。
- `取消`：放弃本次编辑。
- Local 模式下，当前配置模型在客户端、Agent 或当前 Runtime 的 llama 服务任一运行时禁止编辑参数；其他可用模型仍可编辑。自动适配要求处于 OpenAI 模式，且当前 Runtime 的 llama 服务已停止。

### 沙箱设置

- 此页为当前模型保存 Codex 命令沙箱权限，与 llama.cpp 参数和审批方式分开管理。
- 自定义路径入口保留；旁边的“添加常用目录 ▾”提供 Gradle、Kotlin Daemon、Maven、npm、pip、NuGet、Hugging Face 目录复选菜单。首次展开异步识别，可刷新，默认不勾选；确认“添加所选”后统一进入现有列表，仍可修改或移除权限。缓存默认读写，Hugging Face 默认只读。
- Kotlin Daemon 快捷项使用当前用户的 `%LOCALAPPDATA%\kotlin\daemon`，默认读写但不自动勾选；目录未创建时也可预先添加，不扩大到整个 AppData。保存后重新启动客户端生效。
- 常用目录优先读取环境变量和工具配置：npm/pip 查询本机工具，Maven 识别用户 settings.xml 的 localRepository，Gradle/NuGet/Hugging Face 识别对应环境变量及已有默认目录。无法确认时显示“未识别”，请用自定义路径选择（例如 Maven 使用额外命令行配置或工具未在 PATH 中）；明确配置但尚不存在的目录允许添加，不自动创建。已添加路径不重复添加，也不自动升级权限。
- 联网选项为“沿用 Codex 默认联网设置”“禁止命令联网”或“完整联网”。联网设置只针对受沙箱控制的命令；网页、浏览器和连接器仍由各自功能与策略控制。
- 额外路径必须是绝对目录。未勾选“允许写入”时授予只读访问；勾选后授予读写访问。不能直接授权整个磁盘或共享根目录。
- 模型 Profile 结构版本为 11。旧 Profile 的沙箱字段为空时，启动器不自动写入沙箱配置，继续使用原有 Codex 设置。只有用户修改沙箱选项后才保存该模型的个性化权限。
- Gradle 快捷项提供默认关闭的“同时设为 Gradle 用户目录”，仅勾选该目录并选择读写时可启用。已添加目录可再次从快捷菜单选择以补充此用途，不自动扩大原读写权限。路径列表保留开关；修改路径同步改变目标，关闭写入/删除路径会提示并取消关联设置。只能设置一个 Gradle 用户目录。
- 启用后仅在 Local 配置的 `shell_environment_policy.set` 中设置 `GRADLE_USER_HOME`，不改系统环境、不覆盖 Java `user.home`、不创建或迁移缓存。该目录也包含 Gradle 用户配置及初始化脚本。已有变量指向不同目录时停止应用并显示两条路径；用户可沿用已有目录，或明确勾选“允许替换已有 Gradle 用户目录（仅本地模式）”。存在无法确认的环境过滤规则/旧快照时停止应用。关闭选项、切模型或回到在线后按原快照恢复环境表；保存后需重启客户端并新建聊天验证。
- `sandbox-environment.concise.jsonl` / `sandbox-environment.full.jsonl` 记录 Gradle 环境配置冲突、写入校验和恢复；完整版额外记录目录。配置写入成功不等同于已有聊天执行环境验证成功。
- Gradle 设置按 Codex 的环境处理顺序检查：`exclude` 在显式 `set` 之前执行，不会阻止此设置；非空 `include_only` 或 `filters` 的 include 白名单必须匹配 `GRADLE_USER_HOME`（支持大小写不敏感的 `*`、`?`）。支持 filters 内联映射或独立子表；混用新旧过滤格式、未知规则值或不支持的点分键/父级内联表会明确提示，启动器不会自动修改白名单。
- 常用目录检测失败时菜单显示重试入口，也可继续使用自定义路径；关闭参数窗口会取消检测并尝试终止工具探测进程，取消结果不会作为识别成功缓存。Gradle 环境诊断使用本次配置事务的数据目录，更新、恢复及回滚沿用恢复记录所在目录，不另写入默认数据目录。
- 模型切换并启动 ChatGPT 时应用该模型的沙箱设置；切回 OpenAI 时恢复原始沙箱字段。审批策略 `approval_policy` 和 reviewer 设置不由此页修改。
- Codex 命名权限配置目前为 beta 能力。若原配置使用 `:danger-full-access` 或命名配置无法保留的临时目录排除规则，切换会安全中止并提示冲突。

## 5. 运行与缓存页

### 设备与运行监控

- CPU：型号、逻辑处理器、实时占用率。
- 内存：模块厂商、容量、类型、频率、已用/总量；系统未公开的字段显示不可用。
- GPU：适配器名称、总占用、Compute/CUDA、总显存和 llama 显存。
- llama 进程：进程数、CPU 和 RAM。
- `/models`：当前模型加载状态。
- `/metrics`：请求、Prompt/输出 token 与 token/s；不支持 metrics 的 Runtime 不阻断核心运行。
- `/slots`：Slot、KV Cache 和实际已用 token。该数值包含系统提示、项目上下文和工具 schema，通常高于窗口可见文字。
- `立即刷新`：主动更新一次所有可用指标。

### 模型驻留控制

- `立即加载当前模型`：调用 llama 原生 `/models/load`。
- `立即释放当前模型`：调用 llama 原生 `/models/unload`；下次请求可重新加载。
- 有活跃请求、状态未知、目标不匹配或服务不可用时禁止操作。

### 缓存管理

- `刷新缓存`：读取 llama 返回的可删除缓存及其来源。
- `删除选中缓存`：仅处理 llama `can_remove=true` 且 Profile 记录为 Launcher 下载的模型。
- 删除前必须确认；Local 运行中、手工 GGUF 和来源不明 Profile 禁止删除。
- 删除模型缓存不会删除官方账户、项目或历史。

## 6. 模型搜索与下载（实验性）

- 搜索框支持按钮或 Enter 搜索公开 Hugging Face GGUF 仓库。
- 页面三个区域依次为输入框、搜索结果、可下载的 GGUF 量化版本，使用统一边界和对齐。
- 鼠标位于结果框内时可滚动结果；到达结果框边界后，滚轮继续滚动外层页面。底部“关闭”按钮右边缘与结果框右端对齐。
- 仓库信息包括作者、用途、许可证、下载量、更新时间和 gated 状态。
- 变体信息包括量化、大小和分片数量。
- `当前模型仓库`：选择搜索结果后用默认浏览器打开对应 Hugging Face 仓库。
- `当前模型版本`：选择量化文件后打开该文件/版本页面；点击空白取消选择时两个跳转按钮同步禁用。
- `下载选中变体`：检查磁盘空间后，通过临时 llama Router 原生下载到 Runtime 的 `models` 目录。

- 下载失败不会影响已经稳定的模型扫描、模式切换和本地推理。

## 7. 上下文压缩

- llama.cpp 按 Context 管理硬容量、KV Cache 和推理。
- Launcher 把每模型 `Context - 安全余量` 写成 Codex 可见的自动压缩线。
- Codex 监控真实 token，并在安全节点通过当前本地模型生成摘要，再用“摘要 + 最近原文”重建历史。
- Launcher 不猜测下一次回答长度，不生成摘要，不限制单次输出，也不保存第二套对话。
- 压缩摘要质量取决于模型能力、量化、KV Cache 精度和 Context；参数修改后会在允许保存时同步到 Profile、BAT、Catalog 和 preset。

## 8. 关闭行为

Local 服务运行时关闭启动器会显示：

- `取消`：返回启动器。
- `仅关闭窗口`：保留 Agent、代理和 llama Router，ChatGPT Local 继续可用。
- `停止服务并退出`：停止启动器拥有的后台服务，但保留 Local 模式与 Profile；已打开的 Local 客户端不能继续请求。

OpenAI 模式关闭启动器时会结束不再需要的 Agent。若正常停止失败，只有在路径、PID、启动时间、协议和心跳全部匹配时才允许询问强制终止；所有权不明的同名进程不会被结束。

## 9. 重要提示与对话框

- `保护旧版配置备份`：建议选择“是”；程序先 DPAPI 加密并回读验证，再删除对应明文备份。选择“否”不会影响当前配置，但以后仍会提示。
- Local 启动确认：显示模型、Context、账户外壳、凭据剥离、权限归属和官方配置恢复说明。

- Context 低于 16K：风险提醒，不阻止用户决定。
- 参数无效：列出全部错误并阻止保存。
- 缓存删除：提示不可逆并要求确认。
- ChatGPT 正在运行：阻止模式切换、Runtime 更换和配置事务。
- 配置冲突：停止写入，要求用户先处理外部修改，不自动覆盖。

## 11. 数据文件与日志

- Launcher 数据与恢复记录：`%LOCALAPPDATA%\ChatGPTLocalLauncher`。
- ChatGPT/Codex 官方配置：只修改受管理字段，不整目录覆盖 `.codex`。
- 官方原始配置备份：当前 Windows 用户 DPAPI 加密。
- 模型 Profile、BAT、模板：位于所选 llama.cpp Runtime 的 `scripts` 目录；当前 Local 的 Router preset 与 Catalog 位于 `%LOCALAPPDATA%\ChatGPTLocalLauncher\generated`，分别为 `models.ini` 和 `local-models.json`。
- 首页“详细日志记录”默认关闭。精简模式记录压缩、服务启停、状态变化和错误；开启后立即切换到完整模式，增加请求阶段、响应传输、异常链/堆栈和 llama.cpp 原生运行日志，正在运行的模型无需重启。
- 日志按模式命名：`agent.concise.jsonl` / `agent.full.jsonl`、`proxy.concise.jsonl` / `proxy.full.jsonl`；Router 文件名包含 `routerRunId` 和模式。结构化日志使用 `schemaVersion=2`，提供 `eventId`、UTC 时间、级别、`sessionId`、`routerRunId` 和事件属性。代理请求使用 `requestId`；重复错误会共享 `failureBurstId`，并记录次数及首次/最近发生时间。
- 日志空间有硬上限：Agent 每个模式最多 3 个 4 MiB 文件；代理每个模式最多 3 个 8 MiB 文件；Router 原生日志每段最多 16 MiB，停止后保留至多 10 个文件。完整模式会增加本地磁盘写入；不会增加模型加载或推理调用。
- 代理结构化日志不记录 Prompt、摘要正文、图片内容、请求/响应正文、认证凭据或完整账户元数据。敏感属性、Bearer 值、长令牌和 Windows 用户目录会脱敏；完整模式的堆栈也会脱敏。llama.cpp 原生日志可能包含模型目录、Runtime 目录等其他路径，分享前请检查。
- 如果 Agent 主日志不可写，Launcher 会尝试将一条有大小和保留上限的应急记录写入 `%TEMP%\ChatGPTLocalLauncher\Launcher.Agent.emergency.jsonl`；代理日志写入失败也会报告到 Agent/应急记录。诊断失败不得中断推理或 Router 输出管道。

## v0.9.4 沙箱联网兼容设置

- **允许命令联网**：开启/关闭控制此模型的 Codex 命令联网权限。中间状态表示沿用 Codex 设置，旧模型不会自动开启联网。保存参数后重新启动客户端，并确认聊天选择 `egg_launcher_active`。
- **联网兼容模式**：默认关闭，仅允许联网时可开启。启动本地模型时读取当前用户的固定系统代理，通过 `shell_environment_policy.set.HTTP_PROXY/HTTPS_PROXY` 传入命令环境；保留已有 `NO_PROXY` 并加入本地回环地址。不修改全局代理、沙箱用户注册表、审批方式或证书验证。PAC、需要账号密码的代理不自动转换；没有固定系统代理时不增加代理变量。部分命令工具未必采用代理环境变量。
- **检查联网**：点击后运行 Codex 自带的独立沙箱和固定只读脚本，不依赖模型调用工具。检查当前编辑的联网/兼容设置；不证明已有聊天已切换，不验证新增目录授权。检测访问百度 HTTPS；可用时比较 Windows TLS 与 Python/OpenSSL。管理员要求仍有效，超时/沙箱接口不兼容/运行组件缺失均显示未完成，不用普通进程代测。首次沙箱初始化可能由 Codex 显示系统提示。
- Windows HTTPS 检查失败而兼容脚本成功时，提示可使用兼容路径，并保留 Windows 异常链；不据此自动断定所有失败均为 TLS 问题。
- 兼容模式同时提供安装目录内的 `Networking/egg-network.py`，使用 Codex 自带 Python/OpenSSL 进行 HTTPS GET/HEAD 和下载；保持证书验证，在当前命令沙箱内运行。不会透明替换 git、包管理器、浏览器或网页搜索功能，也不改变它们的权限。
- 兼容脚本采用两阶段超时：`--request-timeout` 限制代理探测、建立连接、TLS 和重定向至最终响应头的总耗时；`--read-timeout` 限制连续未收到新数据的等待时间。两项默认 30 秒，范围 1–300 秒；旧 `--timeout` 为两项提供默认值，单独指定的新参数优先。持续接收数据的下载没有总时长限制。超时输出 `code=timeout`、`timeout_phase=request/read`，清理未完成临时文件；不提供断点续传。等待进程与下载进程均在当前命令权限内运行。
- 开启时通过 `developer_instructions` 追加工具调用说明，保留原有指令；关闭、切换模型或切回在线模式恢复快照。模型是否按说明调用仍需实测，不能保证所有联网命令自动走兼容工具。旧快照缺少该字段时需先切回 OpenAI 重新建立快照。
- 缺少 Codex Python 运行时会明确提示，启动器不会自动下载安装；沙箱检查使用同一兼容脚本，失败结果区分运行组件、环境过滤、代理 TCP、DNS、证书、超时和 HTTP 状态。代理 TCP 正常不代表 HTTPS 正常。
- 兼容请求默认只返回最多 16 KiB 文字预览（可用 `--preview-bytes` 调整至 64 KiB）。下载使用 `--output` 指定工作区内新文件，默认大小保护上限 256 MiB（可用 `--max-bytes` 调整），写入临时文件，完成后发布；失败清理临时文件，不覆盖已有文件，不自动执行下载内容。
- 兼容脚本是简单 HTTPS 的备用手段，不代替 `pip`、`npm`、Git 等依赖管理工具。下载读取完成后才核对有效的 `Content-Length`；分块传输不拿该字段进行比较。成功输出 `bytes_read` 与 `sha256`（供核对保存文件，不代表已验证来源可信）；失败使用 `incomplete_download`、`download_too_large`、`invalid_response_length`、`destination_exists` 等独立错误码。有临时文件时返回清理结果，不隐藏清理失败。
- “检查联网”无需启动模型或 llama 服务。WindowsApps 内的程序不一定允许启动器直接执行，因此检测复用 Codex 在当前用户 `LocalAppData/OpenAI/Codex/bin` 中准备的完整运行副本；CLI、setup、command-runner 必须在同一目录，并逐个与经过安装身份校验的官方包文件比较 SHA256。副本缺失或版本不匹配时提示先打开/重启官方客户端初始化，不执行未经校验的文件，也不使用 `.sandbox-bin` 中的孤立副本；命令工作目录仍通过 `-C` 指定为临时目录。初始化失败的脱敏原因写入完整版诊断日志。
- 沙箱检测日志：`sandbox-network.concise.jsonl` / `sandbox-network.full.jsonl`，沿用详细日志开关；完整版包含脱敏异常链，不记录代理账号密码、证书或沙箱秘密。
- 检测脚本显式使用 UTF-8 输出，结构化结果采用非 ASCII 转义，避免默认 GBK 控制台与 UTF-8 读取器不一致导致中文乱码；记录实际输出代码页，完整版额外记录异常类型、HRESULT 和可用的 Win32 原生错误码。JSON 文件中的 `\uXXXX` 是正常转义，读取后还原中文，不是乱码。该措施不改变网络权限或证书验证。
- 用户在本地模式期间更改的审批设置不会在切回在线模式时被旧快照覆盖。旧恢复记录没有代理环境快照时，需要先回到 OpenAI 再重新启动本地模型，才能启用兼容模式。

# Egg Launcher 0.9.8 用户功能说明

发布日期：2026-10-18。本文按当前源码说明操作规则；发布范围见[发布说明](release-notes-0.9.8.md)，实测与自动检查范围见[发布检查](release-checks-0.9.8.md)。用户已确认最新测试包运行稳定；Windows 11、ROCm 尚未测试。沙箱设置及在线模型下载仍有各自兼容边界。

## 1. 模式与数据边界

- OpenAI 与 Local LLM 互斥，切换前须完全关闭 ChatGPT Desktop。关闭客户端或启动器不自动切换模式。
- 客户端关闭后可直接从本地模型 A 切到 B，不必先回到在线模式。
- 项目与历史共用，可跨模式查阅。原任务跨 Provider 续聊不在支持范围内，请在目标模式创建新任务继续。
- 本地代理在请求进入 llama.cpp 前剥离 Authorization、Cookie 和账户相关 Header；不修改登录凭据或会话存储路径。
- 切回 OpenAI 恢复进入本地前的官方模型、活动 Provider、思考、上下文、服务层级和权限等受管字段。为查阅旧本地任务保留一个未激活的历史 Provider，不要求配置逐字相同。

## 2. 首页

### 外观、语言与入口

- 设置卡片右上角依次提供 GitHub 主页、语言及明暗主题入口。
- 默认跟随 Windows 显示语言，中文系统使用中文，其他系统使用英文。单击语言按钮固定为中文或英文，右键可恢复跟随系统；系统语言变化后重启启动器生效。
- 浅色与深色使用同一布局。底部提示可关闭，约 10 秒后自动隐藏；新提示会重新计时。
- 环境状态显示客户端、Agent、Router、后端和实际模型。前台低频刷新，后台暂停常规探测；托盘与管理操作按需刷新，不猜测不可用数据。

### 本地模式的 OpenAI 认证

- 启动卡片右上角的钥匙按钮切换认证。强调色为开启，斜线钥匙为关闭；悬停显示当前保存的偏好及锁定原因。
- 新安装及缺少设置字段的旧版本默认关闭。该值保存到启动器 `settings.json` 的 `LocalRequiresOpenAiAuth`，下次本地启动传入 Provider 的 `requires_openai_auth`，不写入任何模型参数 JSON。
- 保存开关不立即改写 Codex 配置，也不表示当前已运行客户端已切换认证。客户端、本地服务运行或启动器忙碌时禁止切换。
- 关闭后本地模式可能不显示官方账户与额度信息，仍可查阅项目和历史。用户已反馈关闭后本地模式不再显示额度；具体界面行为取决于客户端版本。切回在线模式恢复原配置。

### 后台与诊断

- 可启用当前用户的 Windows 登录启动 Agent，不使用管理员服务。启动项必须指向可信固定目录中的同包 Agent。
- “打开诊断日志文件夹”打开 `%LOCALAPPDATA%\ChatGPTLocalLauncher\logs`；详细日志开关可随时切换，无需重启模型。
- 托盘提供打开启动器、启动客户端、当前模式、切换模式和退出；禁用规则与主界面一致。

## 3. 本地模型与模式卡片

### Runtime、扫描与下载

- 选择包含 llama.cpp 可执行文件的 Runtime 根目录，探测版本、Router、模板、设备及相关选项。当前本地模式或服务运行时不能更换 Runtime。
- 扫描 `models` 中单文件、多分片 GGUF 及受支持的缓存布局；缺失分片如实报告，mmproj 和 MTP 外挂不作为主模型添加。
- 添加模型建立稳定模型登记并初始化配置。首次读取元数据识别 Dense/MoE，未知类型由用户指定，不在每次打开时重复扫描。
- 原生自动适配调用 `llama-fit-params`，先展示再确认，不自动套用硬件无关推荐；须先切回在线并停止相关服务。
- 主模型搜索下载使用 llama.cpp Router 原生 API、SSE 进度和最终路径核对。辅助 MTP/mmproj 下载仅保存文件，不自动关联或开启功能。在线下载仍为实验性功能，受 Runtime、网络、代理与 Hugging Face 可访问性影响。

### 已管理模型

- 列表只显示模型类型与名称，不再显示 Vision/MTP 标签、运行参数摘要或配置状态行。
- 底部入口依次为“编辑运行参数”“模型管理”“在模式卡片中显示/隐藏”“从列表中移除”。
- 从列表移除只清理模型登记、匹配的模型启动预选及生成 BAT，保留参数 JSON、模板、外挂和能力记录，不删除模型或缓存。当前已应用模型须先实际切换到在线或另一模型；只停止服务或改变卡片预选不算完成切换。
- 模型文件缺失时显示不可用，可移除旧登记。显示名称仅用于界面，实际绑定使用内部 ID、真实路径及验证依据。

### 模式卡片

- 卡片底部从左到右为“模型管理”“启动配置：名称”“运行参数”，前后两个入口复用模型页操作。
- 两侧按钮等宽，中间启动配置固定宽度；配置名称最多显示约三个汉字宽度，长名称省略，短名称整体居中，中英文均使用固定布局。
- 点击启动配置菜单扫描本模型目录的直属 JSON，勾号表示下次启动使用的文件。选择只更新该模型的配置预选，不保存参数、不检测能力、不选中模型卡片，也不立即启动。
- 打开参数页及配置菜单时按需刷新目录；外部复制的配置须符合模型绑定及格式要求。预选被删除后显示“无”，不自动选择另一配置；“无”是未选择状态的占位提示，不能用它启动模型。
- 正在运行模型的三个入口全部禁用；未运行模型仍可编辑、保存、载入及预选。任何本地服务运行时均禁止能力检测。
- 真正启动时再次读取、校验配置，未刷新界面也不能绕过缺失文件、类型不符或失效能力检查。

## 4. 模型管理

窗口包含模型信息、模型类型、模板管理、MTP 文件管理、视觉模块管理五个选项卡。各资源列表与参数页下拉菜单共享登记依据。

### 模型信息与类型

- 模型信息只显示模型自身资料，例如真实文件、路径、大小、分片、来源和 GGUF 元数据，不夹带运行参数。可单独保存卡片显示名称，不改变内部身份、文件名、已有 JSON 或验证记录。
- 模型类型可选 Dense/MoE。更改只更新模型登记，不覆盖、删除或迁移旧 JSON；旧类型配置禁止载入及新启动，改回匹配类型后才可继续使用。
- 类型影响标签、参数展示和校验，不替代 llama.cpp 对 GGUF 架构的实际识别。

### 模板、MTP 与视觉资源

- 模板管理提供“生成兼容模板”和“添加模板”。生成从当前模型自身模板出发，按已有规则适配并执行隔离渲染检查；添加已有模板沿用原检查方式。检查通过不等于全部对话、工具和图片能力均通过。
- 外部模板只接受 Runtime `scripts/templates` 目录直属 `.jinja`，不含子目录，不能通过目录链接绕过。内置模板不受外部文件目录限制。已有目录外引用保留供修正，不自动搬移或换用别的模板。
- 有效资源重复添加、重复生成会被拦截。生成的兼容模板可作为后续初始化的默认来源，不暗中改写已有 JSON。
- 外置 MTP 先选择文件，再执行原生隔离联合加载及极短推理；成功后登记，不自动开启功能。内置 MTP 沿用候选识别和正式加载确认，没有新增独立检测按钮。
- 视觉添加沿用 GGUF 元数据识别及 Runtime 选项检查，不额外加载模型或发送测试图片。当前功能的“已识别／关联”不等于真实图片推理已验证。
- 每行“移除”只清理当前模型登记，不删除磁盘文件；仍被任何配置引用时拦截，须先修改对应 JSON 的选择，包括功能关闭但保留引用的配置。
- 文件缺失、替换或相关验证依据改变时记录失效，下拉菜单不再将它作为有效资源。已经选择的失效资源如实显示，不静默替换或关闭已保存请求；新启动按实际启用状态检查并拦截。

## 5. 运行参数与多配置文件

选项卡顺序为基础参数、模板设置、思考设置、视觉模块、MTP 推测解码、高级参数、沙箱设置。模型信息与类型已移到模型管理。各页使用统一卡片、字号、间距、双列参数与滚动布局；视觉下拉框下方不再重复显示 mmproj 标题。

### 文件与操作

- 配置唯一位置为 `llama.cpp/scripts/profiles/configurations/<模型ID>`，只接受直属 JSON。显示名称不改变目录名，其他模型的 JSON 即使复制到此目录也不能载入。
- 每套 JSON 保存完整参数及所选资源，未设置的可选参数仍保留空值或继承语义；启动生成器只传递适用且已设置的参数，不把全部字段显式传给 llama.cpp 或 Codex。
- 首次初始化创建“未命名.json”。以后文件被删除不自动复活；无可用配置时显示“无”，可用默认草稿另存为新配置，但未选中有效文件不能启动。
- 右上角分别显示“载入配置”和“启动配置”，隐藏扩展名、长名称省略，未保存时标 `*`；悬停显示路径，点击定位文件。

| 按钮 | 行为 |
| --- | --- |
| 保存为新配置 | 输入名称保存为新 JSON，继续编辑新文件，不改变启动预选 |
| 保存 | 写回当前载入文件，成功后关闭窗口，不改变启动预选 |
| 应用 | 保存当前文件并设为该模型的启动配置，窗口保持打开 |
| 取消 | 关闭并放弃未保存修改，不撤销此前已完成的保存、应用或检测 |
| 载入配置 | 从模型专属目录打开 JSON 编辑，不改变启动预选 |

底部按钮均有中英文悬浮提示。窗口右上角关闭仍会询问未保存修改；载入另一配置前也会处理当前未保存编辑。外部修改后的过期编辑不能直接覆盖，须重新载入或另存。

保存不生成 BAT、Catalog、Router preset，也不改 Codex 受管配置。新启动读取预选的一份快照，校验后重新生成一套运行文件并事务应用；当前运行、休眠唤醒与后台恢复使用已应用快照。外部改名或删除不影响已有会话，但下次新启动不能回退使用旧 BAT。

### 基础参数与上下文

- Context、安全余量和工具结果上限均可输入整数 tokens 或 K，1K=1,024 tokens。令 Context 为 C、余量为 R、显式工具上限为 T：`max(1,024, floor(C/11)+1) ≤ R ≤ C−1,024`，`1,024 ≤ T ≤ R−1`，自动压缩线为 `C−R`。
- `C < 11R` 是约 10% 摘要空间的经验保护，不保证任何输入都不会超限。非法值保留并提示，不能保存；Context 小于 16K 仅提示风险。
- SSE 空闲等待可沿用 Codex 默认或输入以 5 分钟为步进的正整数分钟，最大 35,790 分钟；保存到配置，下一次新启动才应用到本地 Provider，不生成 llama.cpp 参数。切回在线恢复原值。
- GPU Offload、Flash Attention、K/V Cache、Batch、Micro Batch、并发 Slot、空闲释放等保持原有选项；留空的可选参数由 llama.cpp 默认决定。
- 上下文滚动默认关闭。开启前沿用实际滚动能力检测，不能仅凭 `--help` 判定支持；临时加载占用内存显存，必须先关闭相关服务。参数或验证依据变化时缓存失效，不按时间过期。
- 开启/关闭分别生成 `--context-shift` / `--no-context-shift`。`--keep` 在高级页设置，须为小于明确 Context 的非负整数，并确认 Runtime 支持。
- 原生滚动管理模型硬上下文，可能遗忘早期内容；Codex 压缩负责语义摘要和重建历史。启动器不生成摘要、不限制单次回答，也不替在线模式设置本地压缩线。

### 模板设置与思考设置

- 模板设置包含 Jinja 开关及已登记模板下拉。选 GGUF 内置模板使用模型自身模板；关闭 Jinja 时不传递外部模板，保留选择偏好。
- 思考检测使用当前 JSON 实际选定的模板，仍留在思考页。有效结果独立登记，可供同模型、相同验证依据的配置复用；换模板等依据变化时须匹配有效记录或重新检测。
- 原生思考开关、档位、Responses 传递与客户端兼容性分别验证。只提供已确认原始档位，不补齐、不映射、不默认猜测中档。检测期间不允许载入、应用或另存来替换检测对象。
- 启用思考与调节强度分别控制；部分模型在关闭思考时不能实际应用档位，操作前沿用现有提醒。默认强度仅从已确认档位选择，反转只改变显示顺序。
- “显示思考过程”默认关闭，需要有效开启思考。展示原始思考，不生成另一份摘要；保留原生内容，后续输入只清除完全相同的展示副本。切回在线恢复原显示设置。
- 原生模板渲染与 Responses 提示词验证使用隔离固定测试输入；不会读取真实对话来做能力检测。

### 视觉、MTP 与高级参数

- 在视觉和 MTP 页下拉选择同模型已登记、依据仍有效的资源；选择不会自动开启。关闭功能保留所选资源，允许不同配置使用不同外挂。
- 有效视觉元数据识别记录不因当前 JSON 换用另一模板而被下拉筛掉；原始记录本身失效或 Runtime 明确不支持时仍禁止据此开启。
- 视觉可设投影器 GPU 卸载、Device、Image Min/Max Tokens 和 MTMD Batch Max Tokens；图片输入能力随实际启用状态生成。代理只接受并转发受支持的 `data:image/...`，不代为读取 `file:` 或下载 HTTP(S) 图片。
- MTP 可选内置或已验证外置文件，参数含 N Max、N Min、P Min、P Split、后端采样及外置卸载、设备、K/V Cache、线程等；未设置项沿用 Runtime 默认值。
- 高级参数按 Dense/MoE 展示适用字段，例如线程、加载、设备分配、RoPE/YaRN、检查点及专家放置；实际支持仍由 Runtime 与模型决定。不要把手工修改类型视为改变 GGUF 架构。

## 6. 沙箱与联网

- 沙箱是当前参数 JSON 的运行偏好，与模型能力、llama.cpp 参数和审批方式分开。默认继承 Codex 设置，可选择命令联网和附加只读/读写目录；不能直接授权整个磁盘或共享根。
- 常用目录支持 Gradle、Kotlin Daemon、Maven、npm、pip、NuGet、Hugging Face，首次展开按需识别，默认不勾选；缓存默认读写，Hugging Face 默认只读。不能确认时用自定义路径，不猜测位置。
- Gradle 用户目录为可选项，仅在选定目录且读写时可用，通过 Local 的 `shell_environment_policy.set.GRADLE_USER_HOME` 生效，不改系统环境或迁移缓存。冲突须明确处理。
- 本地启动临时选择 `egg_launcher_active` 权限配置，保留原有基线；切回在线恢复。已有同名配置、无法表示的权限或全盘基线会停止事务，不静默扩大或缩小权限。
- 启动器不写 `approval_policy` 或 `approvals_reviewer`。命令沙箱联网不等同于网页、浏览器或连接器权限。
- “检查联网”使用 Codex 自带独立沙箱和固定脚本，不调用模型；沙箱兼容性、初始化及管理员策略仍可能阻止检查，不用普通进程伪装通过。

## 7. 运行、缓存与退出

- 监控使用 Windows/驱动计数及 llama `/models`、`/metrics`、`/slots`，显示 CPU、内存、GPU、速度、KV 和 Slot；不可用数据明确标注，不为监控唤醒休眠模型。
- 立即加载/释放调用 Router 原生接口，不改变持久化模式。缓存删除须通过原生 `can_remove` 及下载来源检查，Local 运行期间禁止删除。
- OpenAI 模式退出时结束无用 Agent；Local 模式可仅关闭窗口保留服务，或停止代理、Router 和 Agent 后退出。停止服务不自动切回在线。
- Agent 身份、协议、路径、进程启动时间与心跳必须匹配；不结束无法确认归属的同名进程或占用端口的未知进程。

## 8. 数据文件与诊断日志

- 启动器数据根目录：`%LOCALAPPDATA%\ChatGPTLocalLauncher`。全局设置为 `settings.json`，受管恢复记录独立保存，原官方备份按当前 Windows 用户 DPAPI 加密。
- 模型登记为 Runtime `scripts/profiles/<模型ID>.json`；用户配置为 `scripts/profiles/configurations/<模型ID>/*.json`；资源记录为 `scripts/model-resources/<模型ID>.json`；外部模板为 `scripts/templates/*.jinja`。
- 全局 Catalog/Router preset 在数据目录 `generated/local-models.json`、`generated/models.ini`；`generated/applied-local-run.json` 记录已应用快照。用户参数 JSON 不创建 `.bak`，不从旧备份自动复活已删除配置。
- 日志位于数据根目录的 `logs`：`launcher.concise/full.jsonl`、`agent.concise/full.jsonl`、`proxy.concise/full.jsonl` 及带运行标识的 Router 日志。关闭详细模式保留关键结果、拦截与错误，开启后增加阶段、耗时、异常栈和原生日志。
- 新增日志覆盖配置、资源、模型信息/类型、卡片预选、启动、认证和恢复，不逐次记录参数输入、下拉点击或悬停。认证偏好、请求应用值、成功应用值分别记录，避免把偏好误认为当前客户端状态。
- Router 版本优先解析 `llama-server --version`，再回退产品/文件版本；查询有短超时，当前程序未变时复用内存结果，失败不阻止启动。
- JSONL 使用已有 schema、关联 ID、脱敏和轮转；不记录对话/模板/配置正文或凭据。原生详细日志仍可能含本机文件路径，分享前检查。日志写入失败不影响保存、推理或恢复。

## 9. 安装、升级与卸载

- 当前用户安装的 Windows x64 EXE 包含 .NET Runtime，不包含 ChatGPT Desktop、llama.cpp 或模型，不自动启用登录启动；安装器与程序使用作者自签名证书，见[签名策略](signing-policy.md)。
- 覆盖升级或卸载前正常退出客户端、启动器与 Agent。卸载必要时先通过独立事务恢复 OpenAI，失败则停止卸载；缺失用户 JSON 不应阻止恢复。
- 卸载保留历史 Provider、启动器数据、Runtime 和模型，只移除安装文件、快捷方式及匹配安装路径的启动项。旧便携文件不自动删除。
- 0.9.7 安装/升级/卸载恢复已由用户实测；0.9.8 用户确认最新测试包稳定，不据此宣称所有安装故障注入或硬件组合均已逐项通过。完整矩阵见[验收清单](manual-acceptance-checklist.md)。

## 附录：沙箱联网兼容设置

- **允许命令联网**：开启/关闭控制当前配置的 Codex 命令联网权限。中间状态表示沿用 Codex 设置，旧模型不会自动开启联网。保存参数后重新启动客户端，并确认聊天选择 `egg_launcher_active`。
- **联网兼容模式**：默认关闭，仅允许联网时可开启。启动本地模型时读取当前用户的固定系统代理，通过 `shell_environment_policy.set.HTTP_PROXY/HTTPS_PROXY` 传入命令环境；保留已有 `NO_PROXY` 并加入本地回环地址。不修改全局代理、沙箱用户注册表、审批方式或证书验证。PAC、需要账号密码的代理不自动转换；没有固定系统代理时不增加代理变量。部分命令工具未必采用代理环境变量。
- **检查联网**：点击后运行 Codex 自带的独立沙箱和固定只读脚本，不依赖模型调用工具。检查当前编辑的联网/兼容设置；不证明已有聊天已切换，不验证新增目录授权。检测访问百度 HTTPS；可用时比较 Windows TLS 与 Python/OpenSSL。管理员要求仍有效，超时/沙箱接口不兼容/运行组件缺失均显示未完成，不用普通进程代测。首次沙箱初始化可能由 Codex 显示系统提示。
- Windows HTTPS 检查失败而兼容脚本成功时，提示可使用兼容路径，并保留 Windows 异常链；不据此自动断定所有失败均为 TLS 问题。
- 兼容模式同时提供安装目录内的 `Networking/egg-network.py`，使用 Codex 自带 Python/OpenSSL 进行 HTTPS GET/HEAD 和下载；保持证书验证，在当前命令沙箱内运行。不会透明替换 git、包管理器、浏览器或网页搜索功能，也不改变它们的权限。
- 兼容脚本采用两阶段超时：`--request-timeout` 限制代理探测、建立连接、TLS 和重定向至最终响应头的总耗时；`--read-timeout` 限制连续未收到新数据的等待时间。两项默认 30 秒，范围 1–300 秒；旧 `--timeout` 为两项提供默认值，单独指定的新参数优先。持续接收数据的下载没有总时长限制。超时输出 `code=timeout`、`timeout_phase=request/read`，清理未完成临时文件；不提供断点续传。等待进程与下载进程均在当前命令权限内运行。
- 开启时通过 `developer_instructions` 追加工具调用说明，保留原有指令；关闭、切换模型或切回在线模式恢复快照。模型是否按说明调用仍需实测，不能保证所有联网命令自动走兼容工具。旧快照缺少该字段时需先切回 OpenAI 重新建立快照。
- 缺少 Codex Python 运行时会明确提示，启动器不会自动下载安装；沙箱检查使用同一兼容脚本，失败结果区分运行组件、环境过滤、代理 TCP、DNS、证书、超时和 HTTP 状态。代理 TCP 正常不代表 HTTPS 正常。
- 兼容请求默认只返回最多 16 KiB 文字预览（可用 `--preview-bytes` 调整至 64 KiB）。下载使用 `--output` 指定工作区内新文件，默认大小保护上限 256 MiB（可用 `--max-bytes` 调整），写入临时文件，完成后发布；失败清理临时文件，不覆盖已有文件，不自动执行下载内容。
- 兼容脚本是简单 HTTPS 的备用手段，不代替 `pip`、`npm`、Git 等依赖管理工具。下载读取完成后才核对有效的 `Content-Length`；分块传输不拿该字段进行比较。成功输出 `bytes_read` 与 `sha256`（供核对保存文件，不代表已验证来源可信）；失败使用 `incomplete_download`、`download_too_large`、`invalid_response_length`、`destination_exists` 等独立错误码。有临时文件时返回清理结果，不隐藏清理失败。
- “检查联网”无需启动模型或 llama 服务。WindowsApps 内的程序不一定允许启动器直接执行，因此检测复用 Codex 在当前用户 `LocalAppData/OpenAI/Codex/bin` 中准备的完整运行副本；CLI、setup、command-runner 必须在同一目录，并逐个与经过安装身份校验的官方包文件比较 SHA256。副本缺失或版本不匹配时提示先打开/重启官方客户端初始化，不执行未经校验的文件，也不使用 `.sandbox-bin` 中的孤立副本；命令工作目录仍通过 `-C` 指定为临时目录。初始化失败的脱敏原因写入完整版诊断日志。
- 沙箱检测日志：`sandbox-network.concise.jsonl` / `sandbox-network.full.jsonl`，沿用详细日志开关；完整版包含脱敏异常链，不记录代理账号密码、证书或沙箱秘密。
- 检测脚本显式使用 UTF-8 输出，结构化结果采用非 ASCII 转义，避免默认 GBK 控制台与 UTF-8 读取器不一致导致中文乱码；记录实际输出代码页，完整版额外记录异常类型、HRESULT 和可用的 Win32 原生错误码。JSON 文件中的 `\uXXXX` 是正常转义，读取后还原中文，不是乱码。该措施不改变网络权限或证书验证。
- 用户在本地模式期间更改的审批设置不会在切回在线模式时被旧快照覆盖。旧恢复记录没有代理环境快照时，需要先回到 OpenAI 再重新启动本地模型，才能启用兼容模式。

# Egg Launcher 0.9.1 公测版发布说明

发布日期：2026-09-21
开发者：甲总不是贾总
目标系统：Windows 10 22H2 / Windows 11 x64

## 发布结论

0.9.1 是在 0.9.0 核心切换与恢复链路稳定基础上的完整体验升级。版本重点不是替换 llama.cpp 的能力，而是把模型类型、原生参数、MTP、视觉、下载缓存、状态显示和桌面交互整理成可验证、可回退、按模型隔离的管理流程。Release 构建、格式检查、249 项自动化测试、发布后 Agent 自检与 ZIP 逐文件校验均通过。

## 主要变化

- 全新深色/浅色界面、统一矢量图标、标题栏/主界面 Logo、托盘蛋形图标、轻量动画和自适应窗口布局。
- 中文/英文完整界面，默认跟随 Windows 显示语言，可手动固定并恢复自动模式。
- 托盘菜单与状态提示按需刷新，支持打开 Egg Launcher、启动 ChatGPT、查看当前模式、切换 OpenAI/Local 和退出。
- 新模型添加时一次性识别 Dense/MoE；未知类型必须由用户指定，更改类型会重建参数配置，避免参数串用。
- 参数窗口改为基础参数、视觉模块、MTP 推测解码、高级参数、模型信息五个选项卡；未设置项目不写入 Profile，继续采用 llama.cpp 默认值。
- 思考档位由本地模型管理显式检测，只有能力和档位均可验证时才允许开启；关闭或未知能力不参与 Local 启动检查。
- 内置/外置 MTP 与视觉模块均采用“识别或选择—隔离验证—建立关联—参数页启用”的流程；取消关联不会删除辅助文件。
- Hugging Face 搜索增加仓库/版本跳转、主模型/MTP/mmproj 区分和单文件下载。主模型下载完成后自动登记；辅助文件保持未关联状态。
- 支持 llama 原生 Hugging Face 缓存目录、无扩展名 blob、多分片 GGUF 和直接 GGUF；扫描排除已经管理的模型。
- 模型从管理列表移除时只清理 Profile 和受管生成物，不删除磁盘模型；模型文件被外部删除时条目变灰并可重新添加重建配置。
- 设置保存、动画、托盘生命周期和状态检测完成竞态治理；主窗口后台时停止周期状态探测。

## 保持不变的核心边界

- llama.cpp 仍是唯一 Local 推理运行时；Launcher 不实现推理、KV Cache、采样、调度或模型格式转换。
- Codex 负责本地上下文压缩；Launcher 只同步模型 Context 与压缩安全线。
- OpenAI / Local 切换继续使用字段级事务、DPAPI 恢复点和跨进程锁；不读取或替换 `auth.json`。
- MTP、视觉、思考档位和计算后端以 GGUF 元数据、llama.cpp 公开能力和隔离验证结果为准；未知能力不会被猜测为支持。

## 升级说明

- 将 v0.9.1 解压到独立目录，不要覆盖正在运行的旧目录。
- 升级前完全退出 ChatGPT Desktop，并通过旧版正常停止 Launcher 管理的 Local 服务。
- 0.9.0 已管理且没有模型类型字段的 Profile 会显示类型未指定；先在本地模型管理选择 Dense 或 MoE，之后才能编辑运行参数。
- 更改已确定的模型类型会重建该模型参数配置；原模型文件不会被修改。
- 旧模型不会在每次启动时重新扫描类型或能力。思考档位、外置 MTP 和视觉模块均由用户显式检测或关联。

## 已知限制

- 在线下载为实验性功能，依赖 llama.cpp 构建、Hugging Face 可访问性、VPN/代理方式、TLS 与磁盘空间；能搜索不代表 llama.cpp 子进程一定能使用同一网络路径。
- MTP 和视觉辅助文件必须与主模型及当前 Runtime 匹配；验证失败只报告真实错误，不自动更换文件或参数。
- 不同模型对思考档位的声明并不统一。只有检测结果能明确列出支持档位时开关才可用。
- CUDA 已完成主要真机验证；Vulkan、ROCm、不同驱动和更多 llama.cpp 版本仍需按验收清单复测。
- 本地模型的工具调用、视觉理解、MTP 收益和压缩摘要质量由模型、量化、模板、上下文与 Runtime 共同决定。

## 完整性

- 自包含包附带 .NET Runtime 对应许可文件、`BUILD-INFO.txt` 和逐文件 `SHA256SUMS.txt`。
- ZIP 同目录提供 `.sha256` 校验文件。
- 未签名内部测试包会在 `BUILD-INFO.txt` 明确记录 `Signature=unsigned`；正式对外分发应遵循[签名策略](signing-policy.md)。

## 审查中发现并修复

- Windows 上迁移时仍持有原登记文件读取句柄，导致原子替换被拒绝：反序列化后先释放句柄。
- 用户配置失效可能让模型从列表消失：保留模型登记并记录配置错误，新启动阻止，允许重新载入修复。
- 已应用登记中遗留的已启用 MTP 附件被删除，会在读取用户 JSON 前使登记校验失败：登记校验不再要求旧附件存在，资源迁移仍可进行；新启动继续严格检查当前配置，避免回退到旧 BAT。
- 已迁移模型不再因已取消的旧“恢复默认值”快照引用了缺失附件而阻止修复；旧数据保留，新配置的运行参数仍完整验证。
- 配置选择与运行参数保存混在旧的生成链路：编辑器文件操作不再写 BAT、Catalog、preset 或 Codex；应用只提交每模型配置预选。
- 模型类型初次指定可能被可信绑定覆盖：显式模型类型变更更新登记和当前配置，普通导入仍不能覆盖模型身份/缓存来源。
- 资源文件删除后可能从更新后的登记快照再次继承配置声明：迁移只进行一次，后续丢失资源记录不凭配置标志恢复证据。
- 不同主模型可能复用友好模型 ID：资源记录额外匹配具体主模型路径绑定，防止错误继承。
- 同一视觉附件在不同模板下的结果互相覆盖：按验证指纹保留不同上下文，不将分别有效推导为任意组合有效。
- 运行中读取用户 JSON 刷新思考显示或后台重启，可能混入下次参数：运行使用独立已应用快照；已有会话恢复不重新读取用户 JSON。
- 仅比较 preset 无法发现 SSE/工具预算等 Codex 专属参数变化：新 Agent 恢复也读取已提交运行快照，不据修改后的 JSON 改变运行行为。
- 模式配置失败时 BAT/运行快照可能没有一起回滚：两者纳入原模式切换生成物事务。
- 编辑器内部模板文本初始化/选项卡事件可能误标未保存，资源下拉可能显示 record 原文：过滤非参数事件并提供明确显示标签。
- 配置完整性、内容版本摘要和外部覆盖冲突检查补齐；未保存编辑不会悄悄覆盖外部新内容。
